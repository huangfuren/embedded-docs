## 4.1 struct 与内存对齐 ★

**定义**：struct 把多个不同类型的变量**打包成一个整体**——成员在内存里按声明顺序连续存放。但"连续"不等于"紧贴"：**内存对齐**（编译器把每种成员放到"自己宽度的整数倍"地址上，牺牲空隙换访问速度）会往中间塞空隙——这个空隙叫 **padding**。

**完整示例**（`struct_align.c`）：

```c
#include <stdio.h>

struct A { char c;  int i;  char c2; };        /* natural alignment */
struct B { int i;   char c;  char c2; };       /* same members, reordered */
#pragma pack(push, 1)
struct C { char c;  int i;  char c2; };        /* packed: no padding */
#pragma pack(pop)

int main(void)
{
    struct A a; struct B b; struct C c;
    printf("sizeof A(char,int,char) = %zu\n", sizeof a);
    printf("  offset c = %zu, i = %zu, c2 = %zu\n",
           (size_t)((char*)&a.c - (char*)&a), (size_t)((char*)&a.i - (char*)&a),
           (size_t)((char*)&a.c2 - (char*)&a));
    printf("sizeof B(int,char,char) = %zu   <- same members, reordered\n", sizeof b);
    printf("sizeof C packed(1)      = %zu   <- padding removed\n", sizeof c);
    return 0;
}
```

**跟做**：`gcc -Wall struct_align.c -o struct_align.exe` → `.\struct_align.exe`。**预期输出（本机实录）**：

```text
sizeof A(char,int,char) = 12
  offset c = 0, i = 4, c2 = 8
sizeof B(int,char,char) = 8   <- same members, reordered
sizeof C packed(1)      = 6   <- padding removed
```

**三处必看的机制**：① 同样三个成员（1+4+1=6 字节），struct A 占 **12 字节**——c(偏移0) 与 i 之间塞了 3 字节 padding、c2 后又补 3 字节（对齐规则：int 必须住在 4 的倍数地址上）；② **只把成员按"从大到小"重排（struct B），就从 12 缩到 8**——不付任何代价的优化，嵌入式内存紧张时是白捡的；③ `#pragma pack(1)` 强制紧贴（6 字节），但代价是成员可能跨地址边界访问变慢——通信协议报文解析用它，普通数据结构别用。

**对齐两准则与 offsetof**（`offsetof_demo.c`）——把"对齐规则"变成可测量的偏移量。两准则：**每个成员的偏移量是其自身大小的整数倍；结构体总大小是最大成员大小的整数倍**。`offsetof(类型, 成员)`（`<stddef.h>`）直接给出成员的字节偏移：

```c
#include <stdio.h>
#include <stddef.h> /* offsetof */

struct Student1
{
    char c1;
    char c2;
    int n;
};

struct Student2
{
    char c1;
    int n;
    char c2;
};

int main(void)
{
    /* offsetof：成员在结构体里的字节偏移量——对齐规则的直接观察窗 */
    printf("Student1: c1@%zu c2@%zu n@%zu, sizeof=%zu\n",
           offsetof(struct Student1, c1), offsetof(struct Student1, c2),
           offsetof(struct Student1, n), sizeof(struct Student1));
    printf("Student2: c1@%zu n@%zu  c2@%zu, sizeof=%zu\n",
           offsetof(struct Student2, c1), offsetof(struct Student2, n),
           offsetof(struct Student2, c2), sizeof(struct Student2));
    return 0;
}
```

**预期输出（本机实录）**：

```text
Student1: c1@0 c2@1 n@4, sizeof=8
Student2: c1@0 n@4  c2@8, sizeof=12
```

**读法**：Student1 的 n 偏移 4（int 要落在 4 的倍数上，c1/c2 后空 2 字节）、总大小 8（补到 int 宽度的倍数）；同样的三个成员换个顺序（Student2），n@4、c2@8、总大小 **12**——**成员顺序就是内存布局**，这两条准则加上偏移量公式，任何 struct 的 sizeof 都能纸上算出来。`#pragma pack(4)` 把对齐基数压到 4：`{int a; double d; char c}` 从默认的 **24** 变 **16**（本机实测，`pack_demo.c`）——pack(n) 的规则是"成员偏移按自身大小与 n 中较小者的倍数对齐"。

**试一试**：给 struct A 再加一个 `double d;` 放最后，重跑看 sizeof（8 字节成员会改变整体对齐要求）。

## 4.2 union：同一格子的两种解释 ★

**定义**：union 的所有成员**共享同一块内存**——大小等于最大成员。它不是"多个值"，而是**同一串二进制的多种解释**——正是「C语言」002 §2.1"类型 = 宽度 + 解释"的工具化。

**完整示例**（`union_view.c`）：

```c
#include <stdio.h>

union view {
    int          i;                /* read as 32-bit int */
    unsigned char b[4];           /* read as 4 bytes */
};

int main(void)
{
    union view v;
    v.i = 0x12345678;             /* same 4 bytes, two interpretations */
    printf("as int       : 0x%X\n", v.i);
    printf("as bytes[0..3]: %02X %02X %02X %02X  (little-endian: LSB first)\n",
           v.b[0], v.b[1], v.b[2], v.b[3]);
    return 0;
}
```

**跟做**：编译运行。**预期输出（本机实录）**：

```text
as int       : 0x12345678
as bytes[0..3]: 78 56 34 12  (little-endian: LSB first)
```

**读法**：写入 0x12345678，按字节读出来是 **78 56 34 12**——最低有效字节在最低地址，这就是**小端序（little-endian）**的本机实拍（「计算机体系结构」001 §1.4 立过名词，这里亲眼看）。**嵌入式用途**：拆寄存器值看字节、通信协议收到的字节流重组为 int——union 是嵌入式"字节级思考"的标准工具。

**试一试**：把 `v.i` 改成 `0x00000001` 再看字节——`01 00 00 00`，确认"低位在低地址"；再把 union 加一个 `short s;` 成员打印，体会"union 大小 = 最大成员"；用**指定初始化器**给非首成员赋值：`union view v2 = {.b = {0x78, 0x56, 0x34, 0x12}};`（C99 起支持 `.成员` 指定写法，不指定成员时只能初始化首成员 `union view v3 = {5};`）。

## 4.3 位域：按位打包的成员 ★

**定义**：位域（bit field）让 struct 的成员按**位**分配宽度——硬件寄存器常按位定义字段（[3:0] 是一个功能、[7:4] 是另一个），位域是 C 对这种布局的直接表达。

**完整示例**（`bitfield.c`）：

```c
#include <stdio.h>

struct flags {
    unsigned mode  : 3;           /* 0..7   */
    unsigned enable: 1;           /* 0..1   */
    unsigned speed : 4;           /* 0..15  */
};

int main(void)
{
    struct flags f = {0};
    printf("sizeof flags = %zu byte(s)\n", sizeof f);
    f.mode = 7; f.enable = 1; f.speed = 15;
    printf("mode=%u enable=%u speed=%u\n", f.mode, f.enable, f.speed);
    f.mode = 8;                    /* overflow: 3 bits can hold 0..7 */
    printf("after mode=8 -> mode=%u  (wraps like uint8_t did!)\n", f.mode);
    return 0;
}
```

**跟做**：编译运行。**预期输出（本机实录，含编译器警告——警告本身就是教材）**：

```text
bitfield.c:15:14: warning: unsigned conversion from 'int' to 'unsigned char:3' changes value from '8' to '0' [-Woverflow]
sizeof flags = 4 byte(s)
mode=7 enable=1 speed=15
after mode=8 -> mode=0  (wraps like uint8_t did!)
```

**三处机制**：① 3+1+4=8 位，但 sizeof 是 **4 字节**——位域至少按存储单元（int）对齐分配，别指望它省到 1 字节；② `f.mode = 8` 超出 3 位容量，编译器**警告**且运行回绕成 0——和 types.c 的 `uint8_t 255+1` 是同一种回绕；③ **边界与风险**：位域的跨字节布局由实现定义——映射硬件寄存器时，正式工程优先用"掩码+移位"（「C语言」002 §2.3 模板），位域用于纯软件的状态打包。

**试一试**：把 `mode` 宽度改成 2（能存 0..3），赋值 7 再看警告与回绕值。

## 4.4 枚举与 typedef ○

**定义**：枚举（enum）= 把"取值有限的一类事物"定义成类型——枚举项是命名的整数常量，默认从 0 递增、可自定义值。typedef = 给类型**取别名**——`typedef 类型 别名;`，别名与原类型完全等价，嵌入式头文件里 `u8`、`uint8_t`（§2.1）都是它的产物。

**完整示例**（`enum_typedef.c`）：

```c
#include <stdio.h>

/* 枚举：值有限的类型，默认从 0 递增 */
typedef enum
{
    LED_OFF,
    LED_ON,
    LED_BLINK
} LedState;

/* typedef：给类型取别名，嵌入式惯用法 */
typedef unsigned char u8;

void show(LedState s)
{
    switch (s) /* switch 表达式可以是枚举变量 */
    {
    case LED_OFF:
        printf("LED off\n");
        break;
    case LED_ON:
        printf("LED on\n");
        break;
    case LED_BLINK:
        printf("LED blink\n");
        break;
    }
}

int main(void)
{
    LedState st = LED_ON;
    show(st);
    printf("LED_OFF=%d LED_ON=%d LED_BLINK=%d\n", LED_OFF, LED_ON, LED_BLINK);

    u8 v = 200; /* 别名当类型用，与 unsigned char 完全等价 */
    printf("sizeof(u8) = %zu, sizeof v = %zu\n", sizeof(u8), sizeof v);
    return 0;
}
```

**跟做**：编译运行。**预期输出（本机实录）**：

```text
LED on
LED_OFF=0 LED_ON=1 LED_BLINK=2
sizeof(u8) = 1, sizeof v = 1
```

**三处必看的机制**：① `LED_OFF=0 LED_ON=1`——枚举项默认从 0 递增，写 `enum {A = 10, B, C}` 则 B=11、C=12（自定义起点后继续递增）；② 枚举 + switch 是状态机的标准搭配（002 §2.4 的 switch 表达式"只能是 char/short/int/枚举变量"在此闭环）——比裸数字 0/1/2 可读性高一个量级；③ typedef 只做**改名不做新类型**：`sizeof(u8)` 与 `sizeof(unsigned char)` 同为 1。与 struct 的类比：struct/enum 描述"一类事物"（图纸），具体变量是"对象"（实例）——从面向对象语言转来的读者用这个直觉入门即可。

**试一试**：① 给枚举加自定义值 `LED_SLOW = 10` 放最后，打印三个值验证；② `sizeof(u8)` 写成 `sizeof u8` 会编译报错——**sizeof 类型名必须加括号**（表达式不用），记住这个差别；③ typedef 也能给**指针与数组类型**起别名：`typedef char *String;`（`String s = "hi";` 一眼看出是字符串指针）、`typedef int FiveInt[5];`（`FiveInt arr = {1,2,3,4,5};` 等价 `int arr[5]`）、`typedef int (*ArrPtr)[3];`（数组指针别名，007 §7.3 的格式从此不用手写）。

## 4.5 预处理与头文件工程 ★

**定义**：预处理在编译前对**文本**做替换与裁剪：`#define` 宏（带参数的文本替换）、`#ifdef/#endif` 条件编译（按宏裁剪代码）、头文件守卫（防重复包含）。它们都不是 C 语句——结尾没有分号。

**完整示例**（`macro.c`）：

```c
#include <stdio.h>

#define SQ_BAD(x)  x * x          /* dangerous: no parens */
#define SQ_OK(x)   ((x) * (x))    /* safe: parens everywhere */

int main(void)
{
    printf("SQ_BAD(2+3) = %d   <- 2+3*2+3 = 11, NOT 25!\n", SQ_BAD(2+3));
    printf("SQ_OK(2+3)  = %d\n", SQ_OK(2+3));
#ifdef DEBUG
    printf("DEBUG build\n");
#else
    printf("release build (DEBUG not defined)\n");
#endif
    return 0;
}
```

**跟做**：`gcc -Wall macro.c -o macro.exe` → `.\macro.exe`。**预期输出（本机实录）**：

```text
SQ_BAD(2+3) = 11   <- 2+3*2+3 = 11, NOT 25!
SQ_OK(2+3)  = 25
release build (DEBUG not defined)
```

**机制**：宏是**纯文本替换**——`SQ_BAD(2+3)` 展开成 `2+3*2+3`，先乘后加得 11；参数和整体都加括号才正确（嵌入式宏的黄金法则：**每个参数加括号，整个表达式加括号**）。**条件编译**：`-DDEBUG` 编译（`gcc -Wall -DDEBUG macro.c`）——本机实录第二行变成 `DEBUG build`；调试打印开关、同一份代码适配不同芯片都用它。**头文件工程**：「C语言」001 §1.6 的 `utils.h` 里那行 `int add(int a, int b);` 就是原型声明——`#ifndef X / #define X / #endif` 三件套做守卫，防止头文件被重复包含。

**试一试**：把 `SQ_OK` 的内层括号去掉（改成 `(x * x)`）再用 `SQ_OK(2+3)` 测试——还是 25？换成 `SQ_OK(a++)` 这种带副作用的参数，比较两个宏的结果差异（副作用被执行几次）。

## 4.6 宏与条件编译工程深化 ○

**定义**：本节把宏与条件编译从"会用"推到"工程级"：宏是**纯文本替换**所以副作用参数会翻倍执行；`#undef` 能中途撤销宏；`#if/#elif/#if defined` 让同一份代码按平台/开关自动裁剪——嵌入式跨芯片代码的组织核心。

**带参宏 vs 函数：副作用实测**（`sq_side.c`）——同一个"求平方"，函数版与宏版喂同样的 `i++`：

```c
#include <stdio.h>

#define SQ(x) (x) * (x) /* 宏：纯文本替换 */

int func(int i) /* 函数：参数先求值再拷贝 */
{
    return i * i;
}

int main(void)
{
    /* 函数版：i++ 求值一次，i 逐个走 1..5 */
    int i = 1;
    printf("函数版: ");
    while (i <= 5)
    {
        printf("%d ", func(i++));
    }
    printf("\n");

    /* 宏版：SQ(i++) 展开成 (i++)*(i++)，副作用执行两次 */
    int j = 1;
    printf("宏版  : ");
    while (j <= 5)
    {
        printf("%d ", SQ(j++));
    }
    printf("\n");
    return 0;
}
```

**预期输出（本机实录，含 -Wall 警告）**：

```text
sq_side.c:26:27: warning: operation on 'j' may be undefined [-Wsequence-point]
   26 |         printf("%d ", SQ(j++));
函数版: 1 4 9 16 25 
宏版  : 2 12 30 
```

**读法**：函数版 `func(i++)` 参数求值**一次**，i 从 1 走到 5，输出 1/4/9/16/25；宏版 `SQ(j++)` 展开成 `(j++)*(j++)`——**副作用执行两次**，输出 2/12/30 且序列点警告。这就是"宏没有调用开销但要害死副作用参数"的实证：**带副作用的表达式不要喂宏**。

**条件编译工程用法**（`cond_demo.c`）——`#if 0 ... #endif` 整体丢弃大段代码（比注释干净）；`#if/#elif/#else` 多路开关；`_WIN32`/`__linux__` 是编译器预定义的平台宏，跨平台代码靠它们选头文件与函数：

```c
#if _WIN32      /* Windows 平台宏由编译器预定义 */
    /* Windows 专属代码 */
#elif __linux__ /* Linux 平台 */
    /* Linux 专属代码 */
#endif

#if 0
这段代码被预处理器整体丢弃——临时禁用大段代码的标准做法
#endif
```

**本机实测**（`FLAG` 定义为 2）：输出 `running on Windows, unit=us`——`#elif FLAG == 2` 分支生效。文件包含的路径规则：`<>` 只搜系统目录，`""` **先搜源文件所在目录**（可用 `../inc/x.h` 相对路径、也能写绝对路径）——工程里把头文件分目录（inc/）就用相对路径组织。

**#undef 与宏嵌套**：`#define PI 3.14` 后 `#undef PI` 撤销——PI 之后的代码不再受它影响（宏的作用范围从定义行到 #undef 行）；宏替换文本里可以引用已定义的宏（嵌套展开：`#define S PI * y * y` 展开时 PI 先换成 3.14）。

**试一试**：① 把 cond_demo 的 `#define FLAG 2` 改成 1、删掉再各跑一次，观察三个分支的切换；② 宏版 SQ 里把 `j++` 改成 `++j` 再跑——前后置在双副作用下的输出又不一样（这正是"不要给宏喂副作用"的原因）。

## 4.7 坑表

| # | 现象 | 原因 | 解法 |
|---|---|---|---|
| 1 | struct 大小比成员之和大 | 内存对齐 padding（A=12 实录） | 成员按"从大到小"重排；需要紧贴才用 pack(1) |
| 2 | 跨平台读 struct 字节不对 | 对齐与字节序实现相关 | 通信解析用 pack(1)+显式转换，不直接强转内存 |
| 3 | union 读成员值"错乱" | 共享内存本就如此 | 写 A 读 B 是"换解释"，不是 bug（§4.2 正是靠它工作） |
| 4 | 位域赋值回绕 | 位宽不够（mode=8→0 实录） | 按字段最大值选位宽；开 -Wall 看溢出警告 |
| 5 | 宏算错（25 变 11） | 参数没加括号 | 每参数+整体都加括号；副作用参数慎用宏 |
| 6 | 头文件重复包含报"重复定义" | 没有守卫 | `#ifndef/#define/#endif` 三件套 |
