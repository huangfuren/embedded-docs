## 6.1 函数：封装、四种形态与三种调用 ★

**定义**：函数是封装特定功能、可反复调用的代码块。按"有无返回值 × 有无形参"分四类；调用方式三种——直接调用、输出调用、赋值调用（**推荐**，结果存进变量可继续用）。形参约束实参的**类型、个数、顺序**，与名字无关。

**完整示例**（`func_demo.c`）：

```c
#include <stdio.h>

/* 1. 无返回值无形参 */
void say_hello(void)
{
    printf("hello!\n");
}

/* 2. 无返回值有形参 */
void greet(const char *name, int times)
{
    for (int i = 0; i < times; i++)
        printf("hi, %s\n", name);
}

/* 3. 有返回值无形参 */
int get_answer(void)
{
    return 42;
}

/* 4. 有返回值有形参 */
int add(int a, int b)
{
    return a + b;
}

int main(void)
{
    say_hello();                               /* 直接调用 */
    greet("tom", 2);                           /* 直接调用 */
    printf("answer = %d\n", get_answer());     /* 输出调用 */
    int sum = add(3, 5);                       /* 赋值调用（推荐） */
    printf("sum = %d\n", sum);
    return 0;
}
```

**跟做**：`gcc -Wall func_demo.c -o func_demo.exe` → `.\func_demo.exe`。**预期输出（本机实录）**：

```text
hello!
hi, tom
hi, tom
answer = 42
sum = 8
```

**三处必看的机制**：① 无返回值函数（void）**只能直接调用**——没有结果可接；有返回值函数三种调用都合法，但只有赋值调用把结果留住；② `add(3, 5)` 调用时实参**拷贝**给形参——函数里改 `a`、`b` 不影响外面（002 §2.6 已实证）；③ 形参列表里的 `(void)` 与 `()` 都表示无形参，写 `(void)` 更明确（001 §1.7 的 Makefile 工程里函数已经开始多文件分布）。

**试一试**：① 加第五个函数 `int max2(int a, int b)` 返回较大值，用赋值调用接住；② 故意 `add(3)`（实参个数不符）看编译器怎么说。

## 6.2 函数原型：先声明后调用 ★

**定义**：函数原型（prototype）= 去掉函数体和大括号的**声明**，`返回值类型 函数名(形参列表);`。被调函数定义在调用者**上方**可以不写原型；定义在**下方**必须先写原型——否则新编译器直接**报错**（不再只是警告）。

**完整示例**（`proto_demo.c`）：

```c
#include <stdio.h>

int add(int a, int b); /* 函数原型：声明在前，定义在后 */

int main(void)
{
    printf("add = %d\n", add(2, 3));
    return 0;
}

int add(int a, int b) /* 定义在 main 之后：有原型就无警告 */
{
    return a + b;
}
```

**跟做**：编译运行。**预期输出（本机实录）**：干净通过，输出 `add = 5`。删掉第 3 行原型再编译：

```text
no_proto.c: In function 'main':
no_proto.c:7:26: error: implicit declaration of function 'add' [-Wimplicit-function-declaration]
    7 |     printf("add = %d\n", add(2, 3));
      |                          ^~~
```

**三处必看的机制**：① 旧教材常说"没原型会有**警告**"——GCC 14 起升级为**错误**（C 标准早已废除隐式声明），别背旧结论，以你本机编译器为准；② 原型是给编译器看的"名片"：先递名片（声明），见面（定义）可以晚点；③ 多文件工程里原型集中住在**头文件**里（004 §4.5 的头文件守卫），这就是 `#include <stdio.h>` 能让你直接调 printf 的原因。

**试一试**：① 把 proto_demo 的原型与定义都搬到 main 下方、原型删掉，复现 error；② 给 `add` 原型故意写错返回类型（`double add(...)`），看报错指向哪一行。

## 6.3 return 三问 ○

**三问三答**：

| # | 问题 | 答案 |
|---|---|---|
| 1 | void 函数里能用 return 吗 | 能——只起"结束函数"作用，后面**不能**带值 |
| 2 | 一个函数能有多个 return 吗 | 能——单次调用**只执行一个**，谁先命中谁生效 |
| 3 | 想一次返回多个结果怎么办 | `return 1,2,3` 不行（逗号表达式只留最后一个）——要么**返回值 + 指针形参带出**，要么返回数组/结构体（007 §7.4、004 §4.1） |

**机制**：`return` 一执行，函数立刻结束、栈帧出栈（003 §3.4）——多个 return 的函数（如 §6.7 递归的出口与规律两分支）路径要自己画清楚。返回**值**是拷贝（安全），返回局部变量**地址**是悬空（必死，见 §6.5 实录）。

**试一试**：写 `int sign(int x)`，正数返回 1、负数返回 -1、零返回 0——三个 return 一条路径一个，测试 -5、0、7 三个入参。

## 6.4 作用域与生命周期：三类、就近与默认零值 ★

**定义**：作用域（scope）决定一个名字在哪可见：**全局**（整个程序）、**局部**（函数内）、**块级**（大括号内）。同名时**就近原则**生效——块级遮局部、局部遮全局。生命周期与作用域同序：块级 < 局部 < 全局；**只有全局与 static 成员有默认零值**，局部/块级是垃圾值。

**完整示例**（`scope_demo.c`）：

```c
#include <stdio.h>

int x = 1; /* 全局作用域：默认零值，随程序生死 */

void shadow(void)
{
    int x = 2; /* 局部作用域：遮住全局的 x */
    {
        int x = 3; /* 块级作用域：遮住局部的 x */
        printf("block x = %d\n", x);
    }
    printf("local x = %d\n", x);
}

void zero_demo(void)
{
    int local; /* 局部：无默认值（垃圾值） */
    printf("global x = %d (默认零值)\n", x);
    printf("local    = %d (垃圾值)\n", local);
}

int main(void)
{
    shadow();
    printf("global x = %d (就近原则，函数内的遮蔽不影响外面)\n", x);
    printf("---------\n");
    zero_demo();
    return 0;
}
```

**跟做**：编译运行。**预期输出（本机实录，含 -Wall 警告）**：

```text
scope_demo.c: In function 'zero_demo':
scope_demo.c:19:5: warning: 'local' is used uninitialized [-Wuninitialized]
   19 |     printf("local    = %d (垃圾值)\n", local);
      |     ^~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
scope_demo.c:17:9: note: 'local' was declared here
   17 |     int local; /* 局部：无默认值（垃圾值） */
block x = 3
local x = 2
global x = 1 (就近原则，函数内的遮蔽不影响外面)
---------
global x = 1 (默认零值)
local    = 32758 (垃圾值)
```

**三处必看的机制**：① 三个 `x` 互不干扰，各层读到**最近**的那层——函数返回后函数内的 `x` 全部死亡，全局的 `x=1` 原样还在；② 全局 `x` 出生即 0（全局静态区的默认零值），局部 `local` 这次是 32758——**垃圾值每次运行可能不同**，用它等于抽签；③ 生命周期：块级变量随大括号出栈死亡、局部随函数出栈死亡、全局随程序死亡（003 §3.4 的栈与数据段在这里对上号）。

**试一试**：① 把 `zero_demo` 里的 `int local;` 改成 `static int local;`——输出变 0 且多次调用保留（§6.5 的伏笔）；② 在 shadow 的块级里加一句 `x = 99;`，猜猜改的是哪个 x，跑程序验证。

## 6.5 static：延寿、状态保留与文件私有 ★

**定义**：static 修饰谁，谁就"搬家"到全局静态区，获得三效：① **延寿**——随程序加载、随程序死亡；② **默认零值**；③ **文件私有**——static 的全局变量/函数只属于本文件，别的文件 extern 也拿不到。修饰局部变量时最反直觉：**每次调用不再重新出生，跨调用保留状态**。

**完整示例**（`static_demo.c`）：

```c
#include <stdio.h>

void fn(void)
{
    int n = 10; /* 栈上：每次调用都重新出生 */
    printf("fn    : n = %d\n", n);
    n++;
}

void fn_static(void)
{
    static int n = 10; /* 去全局静态区：跨调用保留，且默认零值 */
    printf("fn_st : n = %d\n", n);
    n++;
}

int main(void)
{
    fn();
    fn_static();
    printf("---------\n");
    fn();
    fn_static();
    return 0;
}
```

**跟做**：编译运行。**预期输出（本机实录）**：

```text
fn    : n = 10
fn_st : n = 10
---------
fn    : n = 10
fn_st : n = 11
```

**番外实验**（`ret_addr.c`）——"函数不能返回局部变量地址"三结论一次看清：

```c
#include <stdio.h>

int *bad_ret(void)
{
    int a = 100;
    return &a; /* 局部变量出栈即亡：返回悬空地址 */
}

int val_ret(void)
{
    int a = 100;
    return a; /* 返回值：拷贝，没问题 */
}

int *ok_ret(void)
{
    static int a = 100; /* static 延寿：去全局静态区 */
    return &a;
}

int main(void)
{
    printf("val_ret = %d\n", val_ret());
    printf("*ok_ret = %d\n", *ok_ret());
    int *p = bad_ret(); /* 危险：p 悬空 */
    printf("*p = %d (悬空指针, 值不可信)\n", *p);
    return 0;
}
```

**跟做**：编译运行。**预期输出（本机实录，含 -Wall 警告——警告本身就是判决书）**：

```text
ret_addr.c: In function 'bad_ret':
ret_addr.c:6:12: warning: function returns address of local variable [-Wreturn-local-addr]
    6 |     return &a; /* 局部变量出栈即亡：返回悬空地址 */
      |            ^~
Segmentation fault
```

**三处必看的机制**：① `static_demo` 两函数同代码不同命：普通 `n` 每次调用都从 10 出生、加完即焚；static `n` 第二次调用从 **11** 接着走——状态保留实测；② `ret_addr` 返回局部地址后解引用，本机**段错误直接崩溃**（连 printf 的缓冲输出都随进程一起丢了——缓冲机制 008 §8.2 展开）——返回**值**没问题（拷贝）、返回局部**地址**必死、要返回地址就 `static` 延寿；③ static 局部变量是"函数的记忆"，嵌入式里做事件计数、状态机保持很常见——但它也记住你上次没清理的意外。

**试一试**：① static_demo 里给 `fn_static` 再加 `static int a;`（不初始化），打印它——默认零值实测；② 把 ret_addr 的 `*p` 那行换成写值 `*p = 5;`，重跑看崩溃是否依旧。

## 6.6 extern 与多文件工程 ○

**定义**：extern 是"**声明**这里要用别处定义的东西"——只递名片不盖房。多文件工程里：变量/函数定义在 file01，file02 用 `extern` 声明后即可使用；**static 成员 extern 也拿不到**（文件私有）。链接时把多个 .o 绑在一起（001 §1.6 的链接阶段）。

**完整示例**（`file01.c` + `file02.c`）：

```c
/* file01.c */
#include <stdio.h>

int a = 100;
const double PI = 3.1415;
static char chs[] = "secret"; /* static：只属于本文件，外界拿不到 */

void func(void)
{
    printf("function func\n");
}
```

```c
/* file02.c */
#include <stdio.h>

extern int a;         /* 声明：a 在别的文件里 */
extern double PI;
extern void func(void);

int main(void)
{
    printf("a = %d, PI = %.2f\n", a, PI);
    func();
    return 0;
}
```

**跟做**：两个文件放同一目录 → `gcc -Wall file01.c file02.c -o multi.exe`（多文件一次编译，Makefile 是它的工程化版本）→ `.\multi.exe`。**预期输出（本机实录）**：

```text
a = 100, PI = 3.14
function func
```

**三处必看的机制**：① extern 只**声明**不分配内存——定义（分配）只能有一处，声明可以多处（术语表"声明 vs 定义"一对）；② 试在 file02 里 `extern char chs[];` 并打印——链接期直接 `undefined reference to 'chs'`（本机实录）：**static 的文件私有是链接器在执法**；③ 头文件 + `#ifndef` 守卫（004 §4.5）是 extern 声明的工程化住址。

**试一试**：① 复现 chs 的 undefined reference（真实链接错误文本见上）；② 把 file01 的 `int a` 也加 static，看 file02 的 `extern int a` 报什么错。

## 6.7 递归：找规律找出口 ○

**定义**：递归 = 函数体内调用自己（main 不可以）。**递归不是循环**：递进（规律）+ 回归（出口）两段行程。好递归两条件：有**规律**（n 的问题能化成 n−1 的问题）、有**出口**（最小的 n 直接有答案）。写递归五步：找规律 → 找出口 → 定义函数 → **先写出口** → 再写规律（实参变化要朝出口方向走）。

**完整示例**（`fact_demo.c`）：

```c
#include <stdio.h>

long fact(int n)
{
    if (n <= 1) /* 出口：回归 */
        return 1;
    return n * fact(n - 1); /* 规律：n! = n * (n-1)!，递进 */
}

int main(void)
{
    for (int i = 1; i <= 10; i++)
        printf("%d! = %ld\n", i, fact(i));
    return 0;
}
```

**跟做**：编译运行。**预期输出（本机实录）**：

```text
1! = 1
2! = 2
3! = 6
4! = 24
5! = 120
6! = 720
7! = 5040
8! = 40320
9! = 362880
10! = 3628800
```

**三处必看的机制**：① `fact(5)` 在纸上画展开：5×fact(4)→…→1×fact(0) 出口返回，再逐层回归相乘——每层都是一次真实的函数调用、一层栈帧（003 §3.4）；② 递归深度过深 → **栈溢出**（StackOverflow）——函数没出口或次数太大时；③ `long` 存不下 13! 就该换 `long long`——返回类型与数据规模要一起想（002 §2.1 的宽度）。

**试一试**：① 写 `int sum(int n)` 递归求 1+2+…+n（五步法走一遍）；② 故意把出口条件写成 `if (n < 0)`，传 n=5 看它冲出多远（提前想好 Ctrl+C）。

## 6.8 断点调试：停在你怀疑的行 ○

**定义**：断点调试 = 白盒观察——让程序停在指定行，逐行执行、随时看变量与调用栈，把"猜"变成"看"。VS Code + C/C++ 扩展 + gdb（w64devkit 便携包自带 gdb，本机实测在列）即可调试；IDE 配置细节按 001 边界看官方文档，这里只立方法。

**四步跟法**：

1. **打断点**——行号左侧点一下（再点取消）；一个函数只打一个，打在你怀疑的行；
2. **调试启动**——F5（或 Run and Debug）；程序停在断点行**之前**；
3. **单步推进**——F10 逐过程（把函数当一行）、F11 逐语句（钻进函数内部）；侧栏看变量实时值、调用栈（CALL STACK）能看到一层层函数嵌套；
4. **取消断点**——调试完清点，避免下次误停。

**为什么值得练**：§6.5 的 `static_demo` 用断点单步跑两轮调用，你会**亲眼看见** `fn` 的 n 每次都从 10 出生、`fn_static` 的 n 从 11 接着走——比读十遍文字都结实；递归 `fact(5)` 用调用栈面板看栈帧一层层叠上来又收回去（003 §3.4 的栈可视化）。报错定位（001 §1.6）解决"哪一行错了"，断点调试解决"值为什么变成这样"。

**试一试**：① 在 fact_demo 的 `return n * fact(n - 1);` 打断点，F11 钻进去看 n 的值一路变小；② 在 scope_demo 的块级内打断点，看三个 `x` 各是多少。

## 6.9 坑表

| # | 现象 | 原因 | 解法 |
|---|---|---|---|
| 1 | 调用下方函数报 `implicit declaration` **error** | 新 GCC 已废除隐式声明（旧教材说"警告"过时了） | 写函数原型，或把定义放上方（§6.2 实录） |
| 2 | 返回局部地址 → 段错误崩溃 | 局部变量出栈即亡，地址悬空 | 返回值拷贝，或 `static` 延寿（§6.5 实录） |
| 3 | 函数里改了形参，外面没变 | 实参是拷贝（值传递） | 要改真身传地址（002 §2.6） |
| 4 | 全局变量的值"莫名"变了 | 局部同名遮蔽之外的误改 | 全局少用；改名见名知意（001 §1.4） |
| 5 | `undefined reference to 'chs'` | extern 访问别文件的 static 成员 | static 文件私有，链接器执法（§6.6 实录） |
| 6 | 递归没反应/程序崩 | 没出口或深度过大 → 栈溢出 | 先写出口；深度大改循环 |
| 7 | static 局部变量"记着"上次的值 | 延寿是特性也是副作用 | 要跨调用保留才用 static |
