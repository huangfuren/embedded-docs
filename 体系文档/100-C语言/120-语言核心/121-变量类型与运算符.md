## 121.1 变量与类型：类型 = 宽度 + 解释方式 ★

**定义**：变量是"命名的内存格子"，类型决定格子**占几个字节、按什么格式解释**——同一串二进制按 int 和按 char 解释结果完全不同。

**完整示例**（`types.c`）：

```c
#include <stdio.h>
#include <limits.h>
#include <stdint.h>

int main(void)
{
    printf("char     = %zu byte(s)\n", sizeof(char));
    printf("short    = %zu\n", sizeof(short));
    printf("int      = %zu\n", sizeof(int));
    printf("long     = %zu\n", sizeof(long));
    printf("long long= %zu\n", sizeof(long long));
    printf("float    = %zu\n", sizeof(float));
    printf("double   = %zu\n", sizeof(double));
    printf("int32_t  = %zu\n", sizeof(int32_t));
    printf("int* ptr = %zu\n", sizeof(void *));

    int big = INT_MAX;              /* 2147483647 */
    printf("INT_MAX        = %d\n", big);
    printf("INT_MAX + 1    = %d   <-- overflow wraps!\n", big + 1);

    uint8_t u = 255;
    printf("uint8_t 255 + 1 = %u\n", (uint8_t)(u + 1));
    return 0;
}
```

**跟做**：保存到工程目录 → `gcc -Wall types.c -o types.exe` → `.\types.exe`。**预期输出（本机实录）**：

```text
char     = 1 byte(s)
short    = 2
int      = 4
long     = 4
long long= 8
float    = 4
double   = 8
int32_t  = 4
int* ptr = 8
INT_MAX        = 2147483647
INT_MAX + 1    = -2147483648   <-- overflow wraps!
uint8_t 255 + 1 = 0
```

**三处必看的机制**：① `long` 在 Windows 是 **4 字节**不是 8（LLP64——Windows 64 位数据模型，long 保持 4 字节）——"long 不用管宽度"的直觉在这里破产，嵌入式代码用 `int32_t` 定宽钉死；② `INT_MAX + 1` 得到 **-2147483648**——溢出不是报错而是**回绕**（有符号溢出严格说是**未定义行为**（UB，见 102 全貌），`-O0` 实测回绕是真机表现；真代码靠边界检查防溢出，不依赖回绕——「200 计算机体系结构」001 §1.4 对上）；③ `uint8_t 255+1=0`——8 位无符号 255 再加一回到 0（无符号回绕是标准**保证**的行为），单片机定时器计数器就是这么滚的。

**试一试**：① 声明一个 `int a;` 不初始化直接打印——值是栈上残留（读它是未定义行为，本机那次是 32758，别依赖任何具体值），跑几次对比；② 把 `uint8_t u` 改成从 250 循环加到 258，观察 255→0 的回绕点。

## 121.2 类型细节：占位符、布尔、类型转换与进制 ★

**定义**：三件与类型共处的常用工具——**占位符**（printf/scanf 按"解释方式"取数）、**布尔**（经典 C 没有 boolean 类型：0 假、非零真；C99 起有原生 `_Bool`，C23 起 `bool/true/false` 更是关键字）、**类型转换**（不同宽度类型相遇时的规则：自动提升安全、强制转换有代价）。

**占位符速查**（scanf 里 `%f` 对 float、`%lf` 对 double；printf 里因默认实参提升，float 也用 `%f`）：

| 占位符 | 对应类型 | 例 |
|---|---|---|
| `%d` / `%u` | int / unsigned int | `-42` / `4294967295` |
| `%hd` / `%ld` / `%lld` | short / long / long long | `32767` / `2147483647L` / `9223372036854775807LL` |
| `%lu` / `%llu` | unsigned long / unsigned long long | 嵌入式日志常用（配合 §121.1 定宽类型） |
| `%f` / `%lf` | float / double | `3.14` |
| `%c` / `%s` | 字符 / 字符串 | `'a'` / `"hi"` |
| `%p` / `%zu` | 地址 / sizeof 的结果 | 133 §133.1 实录 |
| `%x` / `%o` | 十六进制 / 八进制 | `0xFF` → `ff` |

**布尔三方案**（C99 起有正式类型；输出一律 `%d`）：

```c
#define BOOL int      /* 方案一：宏（本质） */
#define TRUE 1
#define FALSE 0

_Bool flag = 1;       /* 方案二：_Bool，只装 0/1（不推荐手写） */

#include <stdbool.h>  /* 方案三：bool/true/false（推荐） */
bool ok = true;
```

**类型转换**：转换级别链 `char, short < int < long < long long < float < double < long double`（级别即"谁接收谁不丢信息"——注意级别在本机不等于宽度：§121.1 实测 long 与 int 同为 4 字节）。**自动提升**：大接小无事发生；char/short 参与运算先升 int。**强制转换**：小接大要 `(小类型)` 显式写——代价是精度损失。

**完整示例**（`conv.c`）：

```c
#include <stdio.h>
#include <stdbool.h>

int main(void)
{
    /* 自动提升：大接小，无事发生 */
    short s = 100;
    int num = s;
    printf("num = %d\n", num);

    /* char/short 运算先升 int */
    printf("'0'+'1' = %d (char 运算先升 int)\n", '0' + '1');
    printf("sizeof('0'+'1') = %zu\n", sizeof('0' + '1'));

    /* 强转：丢小数（精度损失） */
    double d = 13.14;
    int t = (int)d;
    printf("(int)13.14 = %d\n", t);

    /* 强转：回绕（精度损失） */
    int big = 200;
    char ch = (char)big;
    printf("(char)200 = %d\n", ch);

    /* 复合赋值隐含强转：a = (int)(a + 20.22) */
    int a = 5;
    a += 20.22;
    printf("a += 20.22 -> a = %d (不是 25.22)\n", a);

    /* bool 输出用 %d */
    bool ok = true;
    printf("bool ok = %d\n", ok);
    return 0;
}
```

**跟做**：`gcc -Wall conv.c -o conv.exe` → `.\conv.exe`。**预期输出（本机实录）**：

```text
num = 100
'0'+'1' = 97 (char 运算先升 int)
sizeof('0'+'1') = 4
(int)13.14 = 13
(char)200 = -56
a += 20.22 -> a = 25 (不是 25.22)
bool ok = 1
```

**三处必看的机制**：① `'0'+'1' = 97`——字符按 ASCII 码值 48+49 参与运算，结果类型 sizeof 实测 4 字节（int）——"char 运算先升 int"不是口诀是实测；② `(char)200 = -56`——200 超出 char 上限 127，补码解释下回绕成 -56（§121.1 溢出回绕的同一物理机制）；③ `a += 20.22` 得 **25** 不是 25.22——复合赋值 `a += x` 的完整展开是 `a = (int)(a + x)`，**隐含了一次强转**，要小数请用 double 变量。

**进制与补码**（一句话版，硬件视角在「200 计算机体系结构」001 §1.4 展开）：四种字面量写法——十进制 `42`、八进制前缀 `0`（`052`）、十六进制前缀 `0x`（`0x2A`）；二进制字面量 C23 才入标准（GCC 扩展 `0b101010` 可用）。**原码**给人看、**补码**给机器算：正数三码合一；负数补码 = 原码符号位不变、其余取反 +1——§121.1 的 `INT_MAX + 1 = -2147483648` 就是补码回绕的直接后果。

**试一试**：① 把 `bool ok = true;` 改成 `ok = 250;` 打印——`_Bool` 存储规则非零归一（得 1）；② 手算 `(char)300` 应为 44（300−256），程序验证；③ `printf("%x\n", 255)` 看十六进制输出。

## 121.3 运算符：除法、短路求值与位运算 ★

**完整示例**（`ops.c`）——整数除法、短路求值、位运算四模板一次看全：

```c
#include <stdio.h>

void print_bin(unsigned v)
{
    for (int i = 7; i >= 0; i--)
        putchar((v >> i) & 1u ? '1' : '0');
}

int side_effect(int x)          /* 用来验证短路：被调用会打印 */
{
    printf("    side_effect(%d) called\n", x);
    return x;
}

int main(void)
{
    printf("5 / 2   = %d   (integer division)\n", 5 / 2);
    printf("5.0 / 2 = %f\n", 5.0 / 2);
    printf("5 %% 2   = %d\n", 5 % 2);

    printf("short-circuit test:\n");
    int r = (0 && side_effect(1));   /* 右边根本不会执行 */
    printf("0 && side_effect(1) = %d\n", r);
    r = (1 || side_effect(2));
    printf("1 || side_effect(2) = %d\n", r);

    unsigned reg = 0x00;
    reg |= (1u << 3);  printf("set   bit3: "); print_bin(reg); printf("  (0x%02X)\n", reg);
    reg &= ~(1u << 3); printf("clear bit3: "); print_bin(reg); printf("  (0x%02X)\n", reg);
    reg ^= (1u << 3);  printf("flip  bit3: "); print_bin(reg); printf("  (0x%02X)\n", reg);
    printf("test  bit3 = %u\n", (reg >> 3) & 1u);
    printf("1 << 4 = %u  (shift = *2)\n", 1u << 4);
    return 0;
}
```

**跟做**：`gcc -Wall ops.c -o ops.exe` → `.\ops.exe`。**预期输出（本机实录）**：

```text
5 / 2   = 2   (integer division)
5.0 / 2 = 2.500000
5 % 2   = 1
short-circuit test:
0 && side_effect(1) = 0
1 || side_effect(2) = 1
set   bit3: 00001000  (0x08)
clear bit3: 00000000  (0x00)
flip  bit3: 00001000  (0x08)
test  bit3 = 1
1 << 4 = 16  (shift = *2)
```

**三处必看的机制**：① `5/2=2` 整数除法截断；② **短路求值被证实**——两行 `= 0/1` 输出后**没有**任何 `side_effect called`：左边已定生死，右边根本没执行（判空再使用 `p && *p` 的安全来源）；③ 位运算四模板在寄存器风格的变量上真实生效——`|=` 置位、`&= ~` 清位、`^=` 翻转、`&` 测试。

**四模板的工业写法**（嵌入式读改写寄存器的标准动作，硬件视角在 500 板块 533 §533.4 展开）：

| 目的 | 写法 | 读法 |
|---|---|---|
| 置位 | `reg \|= (1u << n)` | 把第 n 位置 1，其余不动 |
| 清位 | `reg &= ~(1u << n)` | 把第 n 位清 0，其余不动 |
| 翻转 | `reg ^= (1u << n)` | 第 n 位取反 |
| 测试 | `(reg >> n) & 1u` | 取出第 n 位的值（0 或 1） |

**优先级陷阱**：`&` 的优先级**低于** `==`，所以 `if (reg & 1 == 0)` 会被解释成 `reg & (1 == 0)` 即 `reg & 0`，结果恒为 0——**位运算表达式整体加括号**（`(reg & 1) == 0`）。这条在 121.4 坑表里排第 1。

**试一试**：① 把清位那行删掉，flip 的结果从 00001000 变成 00000000（先清后翻 vs 直接翻的差别）；② 手算 `0x50 | (1u<<3)` 应该是 0x58，写进程序验证；③ 写一句 `if (reg & 1 == 0)` 与 `if ((reg & 1) == 0)`，在 reg=1 时各跑一次，看前者为何永假。

## 121.4 坑表

| # | 现象 | 原因 | 解法 |
|---|---|---|---|
| 1 | `reg & 1 == 0` 恒错（永假） | `==` 优先级高于 `&`，被解释成 `reg & (1==0)` | 位运算表达式整体加括号（§121.3） |
| 2 | `5/2` 得 2 | 整数除法截断 | 浮点运算或显式转型（§121.3 实录） |
| 3 | 浮点 `==` 不成立 | 二进制精度，0.1+0.2 不等于 0.3 | `fabs(a-b) < eps` |
| 4 | `INT_MAX+1` 变负数不报错 | 有符号溢出是 UB，`-O0` 下回绕 | 边界检查；要回绕就显式用无符号（§121.1 实录） |
| 5 | `a += 20.22` 后 a 是 25 不是 25.22 | 复合赋值隐含强转 `(int)(a+20.22)` | 精确累计用 double 变量（§121.2 实录） |
| 6 | `5/2*1.0` 结果还是 2.00 | 从左到右算，`5/2` 已截断 | 先乘 1.0 或写 `5.0/2`（§121.3） |
| 7 | 打印 long 值乱码 | 占位符与类型不匹配（`%d` 对 long） | 按 §121.2 速查表选 `%ld`；开 `-Wall` 会警告 |
| 8 | `(char)200` 得 -56 | 超出 char 范围，补码回绕 | 确认目标类型装得下，或用 `uint8_t`（§121.2 实录） |
