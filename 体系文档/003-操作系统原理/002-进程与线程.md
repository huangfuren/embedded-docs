## 2.1 程序与进程：文件与运行（实验：两个记事本两个 PID） ★

**定义**：程序是磁盘上的**文件**（代码+数据的静态组合）；**进程是程序的一次运行**——代码进内存 + 占着资源 + 处在某个执行状态。同一程序可以开多个进程，互不干扰。

**内核给每个进程建"档案"（PCB，进程控制块）**：进程号（PID）、状态、寄存器快照、内存区域表、打开的文件清单。**切换进程 = 存现场 → 换档案 → 恢复现场**。「C语言」005 §5.4 的内存四区，在进程视角下就是档案里记录的地址空间布局；每个进程的地址互相隔离（**虚拟地址空间**——由内核与 MMU 联手伪造的"独占假象"，本册立名词）。

**完整示例（跟做）**：① 从开始菜单连开两个记事本；② 终端执行：

```powershell
tasklist | findstr /i notepad
```

**预期输出（本机实录）**：

```text
Notepad.exe                  76292 Console                    1     15,108 K
Notepad.exe                  77296 Console                    1     100,364 K
```

**读法**：同一个程序（notepad.exe）出现了**两次**、两个不同的 **PID**（76292 / 77296）、各自独立的内存占用——"程序是文件、进程是运行"的实证。收尾清理：`taskkill /IM notepad.exe /F`。

**试一试**：关掉其中一个记事本再 tasklist——对应 PID 的行消失了，另一个安然无恙（进程隔离的直观体验）。

## 2.2 进程状态与调度：谁下一个上 CPU ★

**三态模型**：**就绪**（万事俱备只差 CPU）→ **运行**（正在 CPU 上）→ **阻塞**（等事件：等 IO、等定时）；事件到来回就绪。**调度器**是内核里决定"下一个上 CPU"的模块；单核上任意时刻只有一个进程在运行，"同时感"来自**时间片轮转**——每个进程跑几毫秒被换下，**上下文切换**（存现场→换档案→恢复现场）微秒级但纯开销。

**FreeRTOS 对照**：RTOS 的"任务"≈ 线程；调度器是**优先级抢占**——高优先级一就绪立刻打断低优先级（「操作系统原理」001 §1.5 的确定响应在此兑现）。

**观察与判断**：程序"假死"没退出 = 阻塞在等某个事件；CPU 100% = 有进程长期占着运行态；系统"卡一下又恢复" = 切换/调度延迟。

## 2.3 线程：共享地址空间的执行流 ★

**定义**：线程是进程**内部**的执行流。同一进程的线程**共享**地址空间（全局变量、堆互相看得见），只各自有独立的栈与寄存器现场。

| | 进程 | 线程 |
|---|---|---|
| 地址空间 | 独立 | 共享所属进程的 |
| 创建/切换开销 | 大（换地址空间） | 小（只换执行流） |
| 数据交换 | 走 IPC（§2.5） | 直接读写共享变量 |
| 隔离性 | 一个崩不影响其他 | 一个崩整个进程陪葬 |

**取舍一句话**：要隔离选多进程，要轻快共享数据选多线程——共享是线程的甜头，也是 §2.4 一切事故的来源。

## 2.4 竞态条件与互斥（实验：丢数与修复） ★

**定义**：**竞态条件** = 多个执行流争同一数据、结果依赖时序。根因一句话：`counter++` 看似一步，硬件上是"读→加→写回"三步，两个线程交错执行时同一份读被加两次只写回一次。

**完整示例 1（`race.c`，不加锁——故意复现）**：

```c
#include <stdio.h>
#include <pthread.h>

#define LOOPS 1000000
int counter = 0;

void *add_million(void *arg)
{
    (void)arg;
    for (int i = 0; i < LOOPS; i++)
        counter++;                    /* read-add-write: NOT atomic */
    return NULL;
}

int main(void)
{
    pthread_t t1, t2;
    pthread_create(&t1, NULL, add_million, NULL);
    pthread_create(&t2, NULL, add_million, NULL);
    pthread_join(t1, NULL);
    pthread_join(t2, NULL);
    printf("counter = %d  (expected %d)\n", counter, 2 * LOOPS);
    return 0;
}
```

**跟做**：`gcc -Wall race.c -o race.exe -pthread` → `.\race.exe`，**连跑三次**。**预期输出（本机实录）**：

```text
counter = 1154649  (expected 2000000)
counter = 1079763  (expected 2000000)
counter = 1074592  (expected 2000000)
```

**丢掉将近一半，且每次数字都不同**——竞态的本质：结果依赖时序。每次少的那部分，就是"读-加-写"三步被打断交错时蒸发的更新。

**完整示例 2（`race_fix.c`，加互斥锁）**——只在 counter++ 外面套上锁：

```c
pthread_mutex_t m = PTHREAD_MUTEX_INITIALIZER;
/* 线程函数里改为： */
    pthread_mutex_lock(&m);
    counter++;
    pthread_mutex_unlock(&m);
```

**跟做**：`gcc -Wall race_fix.c -o race_fix.exe -pthread` → `.\race_fix.exe`。**预期输出（本机实录）**：

```text
counter = 2000000  (expected 2000000)
```

**精确到个位**。互斥锁 = 同一时刻只放一个线程进临界区；代价是吞吐（所以锁只包最小必要段）。**死锁预告**：两把锁、两线程各持一把互等——入门记住一条实操纪律：**多把锁的加锁顺序全局一致**。

**试一试**：把 LOOPS 改成 100 再连跑几次——次数少时竞态窗口小，可能"看起来正确"；数据量一大必现。**"小概率通过"是竞态最危险的伪装**。

## 2.5 进程间通信（IPC）名词图 ○

进程地址空间互相隔离，数据交换必须走内核提供的正式通道：

| 机制 | 形态 | 适合 |
|---|---|---|
| 管道/命名管道 | 字节流，单向 | 父子进程、命令行 `\|` |
| 消息队列 | 离散消息，内核中转 | 结构化命令传递 |
| 共享内存 | 同一块物理内存映射两方 | 大数据量、最快（要自己配锁） |
| 信号 | 异步通知 | 控制：终止/挂起（「计算机体系结构」002 §2.5 catch.c 用过） |
| Socket | 跨机器也通 | 网络服务 |

**跟做（命令行体验管道）**：`tasklist | findstr /i notepad`——`|` 就是管道：tasklist 的输出流进 findstr 当输入，两个独立进程通过内核通道交接数据。FreeRTOS 对照：任务间用队列+信号量，思想同源、形态更轻。

## 2.6 坑表

| # | 现象 | 原因 | 解法 |
|---|---|---|---|
| 1 | 线程开满核数反而更慢 | 上下文切换开销 | 任务数 ≈ 核数 |
| 2 | 计数结果每次都少 | 竞态（race.c 三连丢数实录） | 互斥锁或原子操作 |
| 3 | 一个线程崩全进程死 | 共享地址空间 | 线程纪律或改多进程 |
| 4 | 加锁后性能暴跌 | 临界区太大 | 锁只包最小必要段 |
| 5 | 偶发卡死且两操作并发时必现 | 死锁 | 全局统一加锁顺序 |
| 6 | 小数据量测试通过就上线 | 竞态窗口小而侥幸 | 大数据量压力复测（§2.4 试一试） |
