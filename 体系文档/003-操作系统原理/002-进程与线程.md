## 2.1 程序与进程：文件与运行

**定义**：程序是磁盘上的文件（代码+数据的静态组合）；**进程是程序的一次运行**——代码加载进内存 + 占着一堆资源 + 处在某个执行状态。同一程序可以开多个进程（开两个终端窗口），互不干扰。

**PCB（进程控制块）**：内核给每个进程建的"档案"——进程号、当前状态、寄存器快照、内存区域表、打开的文件清单。**切换进程 = 切换档案**：内核把当前进程的寄存器等现场存进它的 PCB，从下一个进程的 PCB 恢复现场。「C语言」003 的内存四区（代码/数据/栈/堆）在进程视角下就是"这份档案里记录的地址空间布局"。

**隔离的兑现**：每个进程以为自己独占整台机器（靠虚拟地址空间，本册立名词、机制归后续扩册），进程 A 的野指针踩不进进程 B——「操作系统原理」001 §1.4 的隔离在内存维度落地。

## 2.2 进程状态与调度：谁下一个上 CPU

**三态模型**（入门足够）：**就绪**（万事俱备只差 CPU）→ **运行**（正在 CPU 上）→ **阻塞**（等事件：等 IO、等定时），事件到来回就绪。

**调度器**：内核里决定"下一个上 CPU 的是谁"的模块。单核上任意时刻只有一个进程在运行；多进程的"同时感"来自**时间片轮转**——每个进程跑几毫秒就被换下。**上下文切换** = 存现场 + 换档案 + 恢复现场，全程微秒级，但**频繁切换是纯开销**：线程/进程开得太多，时间都花在换人上（误解 3 的根源）。

**FreeRTOS 对照**：RTOS 的"任务（task）"≈ 线程；调度器是**优先级抢占**——高优先级任务一就绪立刻打断低优先级，响应时间可预期（001 §1.5 的 RTOS 分野在这里兑现）。

**观察与判断**：系统"卡一下又恢复"= 切换/调度延迟；某进程 CPU 100% = 它在运行态不下来；程序"假死"但没退出 = 长期阻塞在等某个事件。

## 2.3 线程：共享地址空间的执行流

**定义**：线程是进程**内部**的执行流。一个进程至少一个线程（主线程）；再开的线程与主线程**共享**同一地址空间（全局变量、堆都看得见），只各自有独立的栈和寄存器现场。

| | 进程 | 线程 |
|---|---|---|
| 地址空间 | 独立 | 共享所属进程的 |
| 创建/切换开销 | 大（换地址空间） | 小（只换执行流） |
| 数据交换 | 要走 IPC（§2.5） | 直接读写共享变量 |
| 隔离性 | 一个崩不影响其他 | 一个崩整个进程陪葬 |

**取舍一句话**：要隔离选多进程，要轻快共享数据选多线程——共享是线程的甜头也是一切事故的来源（§2.4）。

## 2.4 并发与同步初见：竞态条件

**并发 vs 并行**：并发 = 单核上交替执行制造"同时感"；并行 = 多核真同时。只要"多个执行流访问同一份数据"，两种形态都会打架。

**竞态条件最小例**：两个线程对同一计数器各加 1 万次：

```c
counter++;   /* 看似一步，硬件上是三步：读、加、写回 */
```

两个线程交错执行"读-加-写"时，同一份读被加两次只写回一次——结果小于 2 万，且**每次跑都不同**。三步中的任何交错都是事故窗口。

**互斥锁**是标准解法：把"读-加-写"包成临界区，同一时刻只放一个线程进去：

```c
pthread_mutex_lock(&m);   /* 进不去就等 */
counter++;                /* 临界区：越短越好 */
pthread_mutex_unlock(&m); /* 放行下一位 */
```

**死锁预告**：两把锁、两个线程各持一把互等——死锁四条件（互斥、持有等待、不可剥夺、循环等待）破坏任意一条即可解；入门记住"加锁顺序全局一致"这一条实操纪律即可。IPC 里的信号量/互斥量与这是同一思想（「C语言」002 的"拿不准加括号"升级成"拿不准加锁"）。

## 2.5 进程间通信（IPC）名词图

进程地址空间互相隔离（§2.1），数据交换必须走内核提供的正式通道：

| 机制 | 形态 | 适合 |
|---|---|---|
| 管道/命名管道 | 字节流，单向 | 父子进程、命令行 `\|` |
| 消息队列 | 离散消息，内核中转 | 结构化命令传递 |
| 共享内存 | 同一块物理内存映射进两方 | 大数据量、最快（要自己加锁） |
| 信号 | 异步通知（"有事发生"） | 控制：终止/挂起 |
| Socket | 跨机器也通 | 网络服务（运维知识库·网络板块的 TCP 通信同源） |

**FreeRTOS 对照**：任务间通信用队列（queue）+ 信号量——思想同源，形态更轻（单地址空间里"共享"是默认态，通信反而要主动隔离）。

## 2.6 坑表

| # | 现象 | 原因 | 解法 |
|---|---|---|---|
| 1 | 线程开满核数反而更慢 | 上下文切换开销 | 任务数 ≈ 核数；IO 密集另算 |
| 2 | 计数结果每次都少 | 竞态：++ 不是原子操作 | 互斥锁或原子操作 |
| 3 | 一个线程崩全进程死 | 共享地址空间 | 线程纪律或改多进程 |
| 4 | 加锁后性能暴跌 | 临界区太大 | 锁只包最小必要段 |
| 5 | 程序偶尔卡死且必现于两操作并发 | 死锁 | 全局统一的加锁顺序 |
| 6 | 共享内存数据"脏读" | 通信没配同步 | 共享内存必须配锁/信号量 |
