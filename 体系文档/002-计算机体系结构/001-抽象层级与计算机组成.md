## 1.1 抽象层级：下层提供服务，上层只管用（纸面作业） ★

**定义**：计算机的一切按"层"组织——每层只依赖下一层的接口、对上层提供服务。这是本库贯穿主线一（根 README）。

| 层（自底向上） | 是什么 | 本库对应册 |
|---|---|---|
| 晶体管 | 最小开关单元：导通/截止 | 「004 电子电路」001 |
| 逻辑门 | 晶体管组成与/或/非 | 「004 电子电路」001~002 |
| 部件 | CPU、存储器、外设控制器 | 本板块 002/003 |
| 指令集（ISA） | 软件与硬件的契约 | 本板块 002 |
| 固件/驱动 | 面向硬件的第一层软件 | 「C语言」005 §5.6 铺垫，实操归规划 005/007 |
| 操作系统 | 硬件资源的总管家 | 「操作系统原理」全板块 |
| 应用 | 你写的程序 | 「C语言」全板块 |

**跟做（纸面作业，写在笔记本上）**：给下面 6 样东西各标一层——① STM32 芯片里的 Flash 控制器；② 你手机上的微信；③ 主板 BIOS；④ `hello.c` 源码；⑤ Windows 管理内存的代码；⑥ `gcc` 翻译出的 hello.exe 里的机器码。**参考答案**：⑤→OS 层；④→应用层的源（它在塔里"斜跨"——写时在应用层，编译后落到 ISA 层）；⑥→ISA/固件之间（可执行文件是 ISA 层的载体）；①→部件层；③→固件层；②→应用层。**判定标准**：说得出"它依赖谁、它服务谁"就算对。

**试一试**：把你最近用过的任何一个软件故障（比如微信卡死）按塔拆一遍——"卡在应用层还是 OS 层？"这就是分层排障的雏形。

## 1.2 冯·诺依曼与哈佛：指令和数据放不放一起 ★

**冯·诺依曼结构**：指令与数据放**同一个**存储器——"存储程序"思想：程序像数据一样存起来，换程序=换存储内容，计算机因此通用。**哈佛结构**：指令与数据**分开**存储、分开通道——取指令与取数据可同时进行。

| | 冯·诺依曼 | 哈佛 |
|---|---|---|
| 指令与数据 | 同一存储器 | 分开存储 |
| 通道 | 共享，可能互相等 | 独立，可并行 |
| 现例 | 通用 PC 的演化主形（缓存调和） | Cortex-M 级 MCU |

**为什么不是考试概念**：它解释了 MCU 的内存现实——程序放 Flash、变量放 SRAM，两边的容量/速度/寿命完全不同（003 §3.3 全部建立在此）。**跟做（观察）**：打开一块 STM32 开发板的参数页（或搜索 "STM32F103C8T6 datasheet"，以官方页为准）：Flash 64KB / SRAM 20KB——两个独立数字，就是哈佛结构在你面前的样子。

## 1.3 五大部件与三种硬件形态：MCU / SoC / PC ★

**五大部件**：运算器（ALU）、控制器（合起来是 CPU）、存储器、输入、输出。现代芯片按集成度分三种形态：

| | MCU（微控制器） | SoC（片上系统） | PC |
|---|---|---|---|
| 典型芯片 | STM32、ESP32 系列 | 骁龙、树莓派 BCM | 台式机 CPU |
| 内存规模 | KB 级（Flash+SRAM） | MB~GB 级 | GB 级 |
| 跑什么 | 裸机 / RTOS | 嵌入式 Linux / Android | 桌面 OS |
| 典型任务 | 控制一个电机、采一个温度 | 手机、网关、智能设备 | 通用计算 |
| 开发方式 | 交叉编译 + 烧录 | 交叉编译 + 系统构建 | 本机编译 |

**跟做（纸上选型）**：三个需求各选形态并给一句理由——① 电饭锅的温度控制（→MCU：KB 级够用、实时、便宜）；② 智能门锁要跑人脸识别（→SoC：算力与 OS 需求）；③ 你正在用的这台电脑（→PC）。**判定标准**：内存量级与"要不要 OS"两条说清即可。

**本机实数锚点**（后两册实验用它）：本机 = AMD Ryzen 7 7840H（8 核 16 线程，3.8GHz）、内存 16GB、L2 8MB / L3 16MB、1TB NVMe——一台标准 PC 形态机器，后面所有实验都在它上面跑。

## 1.4 信息的二进制表示（实验：bin.c 看补码） ★

**定义**：晶体管只有通/断两态，所以信息用二进制。十六进制（0x）是二进制的缩写——1 位 hex 对应 4 位 bin。**字长**：CPU 一次处理的位数，决定寄存器与地址宽度。**补码**：硬件表示负数的方式——正数照写、负数"按位取反加一"，让加法电路不用为负数做特殊设计。

**完整示例**（`bin.c`）：

```c
#include <stdio.h>

int main(void)
{
    unsigned u = 0xFFFFFFFF;
    int    *same = (int *)&u;
    printf("0xFFFFFFFF seen as unsigned = %u\n", u);
    printf("0xFFFFFFFF seen as int      = %d   (two's complement)\n", *same);
    printf("0x1F = %d = binary ", 0x1F);
    for (int i = 7; i >= 0; i--) putchar((0x1F >> i) & 1u ? '1' : '0');
    printf("\n");
    for (int n = 0; n <= 4; n++)
        printf("1 << %d = %u\n", n, 1u << n);
    return 0;
}
```

**跟做**：`gcc -Wall bin.c -o bin.exe` → `.\bin.exe`。**预期输出（本机实录）**：

```text
0xFFFFFFFF seen as unsigned = 4294967295
0xFFFFFFFF seen as int      = -1   (two's complement)
0x1F = 31 = binary 00011111
1 << 0 = 1
1 << 1 = 2
1 << 2 = 4
1 << 3 = 8
1 << 4 = 16
```

**三处必看的机制**：① **同一串二进制，解释方式不同结果不同**——`%u` 读出 4294967295，`%d` 读出 -1（"类型 = 宽度 + 解释"的硬件回声，「C语言」002 §2.1）；② 0x1F 手工对译：`0001 1111` = 16+8+4+2+1 = 31；③ 左移一位 = 乘 2——移位是乘除 2 的硬件捷径。

**试一试**：把 `0xFFFFFFFF` 改成 `0x7FFFFFFF` 再看 `%d` 结果（2147483647——最高位是符号位，这就是 int 正数上限）。

## 1.5 坑表

| # | 现象 | 原因 | 解法 |
|---|---|---|---|
| 1 | 把 MCU 当"小 PC"写代码 | 忽略内存差千倍、无 MMU | 先看 §1.3 表格定形态 |
| 2 | 100 Mbps 当 100 MB/s | bit 与 byte 差 8 倍 | 单位先分清 |
| 3 | 0x1F 手工转二进制出错 | 没用"1 位 hex = 4 位 bin" | 一位一位对译 |
| 4 | 跨平台 int 宽度不一致 | 依赖"int 永远 4 字节" | 用 stdint 定宽类型 |
| 5 | Flash 当 RAM 用写变量 | 非易失存储写入有约束 | 程序与变量分区（003 §3.3） |
| 6 | 负数位运算结果诡异 | 补码与符号位没吃透 | 无符号位域操作用 unsigned |
