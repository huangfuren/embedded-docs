# 301 术语表

> **这一文档回答**：操作系统词汇的准确定义、两个混用词的分界、「症状出现时病根在哪」往哪走。  
> **怎么用**：按名字（按册分组）、按缩写（缩写速查）、按症状（症状反查）。  
> **只有一句话**：要落地动作回对应册；这里保证「认得出、分得清、找得到」。

## 按册分组

### 300 板块级

| 术语 | 英文 | 一句话 |
|---|---|---|
| 操作系统 | Operating System | 管理硬件资源、给应用提供运行环境与服务的系统软件 |
| 内核 | Kernel | OS 的核心：调度、内存、文件、驱动都在这里，常驻内存 |
| 发行版 | Distribution | 内核 + 工具 + 应用打包成的可用系统（Ubuntu/Debian 等） |
| 引导程序 | Bootloader | 加电后把内核从存储搬到内存并启动它的一段程序（U-Boot/GRUB） |
| 根文件系统 | Root Filesystem | 内核启动后挂载的第一套文件系统，init 与库都在里面 |
| 实时性 | Real-time | 系统在确定时间内响应的能力；RTOS 的立身之本 |

### 311 操作系统的四大职责

| 术语 | 英文 | 一句话 |
|---|---|---|
| 复用 | Multiplexing | 让多个程序分享同一套硬件：CPU 轮着跑、内存分着用 |
| 隔离 | Isolation | 一个程序的错误不连累别人；靠特权级与地址空间实现 |
| 进程管理 | Process Management | 决定哪个程序什么时候上 CPU 跑 |
| 内存管理 | Memory Management | 给每个程序分内存、记归属、防互踩 |
| 文件系统 | File System | 把"磁盘上一堆块"抽象成"文件与目录" |
| 设备管理 | Device Management | 用驱动把千差万别的硬件统一成可调用接口 |
| 仲裁 | Arbitration | 资源一份、请求众多，由内核立规矩并强制执行 |
| 外壳 | Shell / GUI | 给人用的交互层；崩了不影响内核运行 |

### 312 启动链：从上电到 shell

| 术语 | 英文 | 一句话 |
|---|---|---|
| 固件 | Firmware | 出厂烧在板子上的启动代码（BIOS/UEFI、芯片 ROM 代码） |
| 自检 | POST | 上电后检查关键硬件是否可用的过程 |
| 复位向量 | Reset Vector | CPU 上电后固定取第一条指令的地址 |
| init / PID 1 | init | 内核拉起的第一个用户态进程，一切用户进程的祖先 |
| 宏内核 | Monolithic Kernel | 调度/文件/驱动全在一个大内核里跑（Linux） |
| 微内核 | Microkernel | 内核只留最小机制，服务放用户态进程（QNX/minix 思路） |

### 313 系统调用与用户态内核态

| 术语 | 英文 | 一句话 |
|---|---|---|
| 用户态 | User Mode | 受限运行级别：不能执行特权指令、不能访问内核内存 |
| 内核态 | Kernel Mode | 特权运行级别：可执行特权指令、访问全部内存 |
| 特权级 | Privilege Level | CPU 区分"应用能干的"与"只有内核能干的"硬件机制 |
| 系统调用 | System Call | 用户程序请求内核服务的唯一正式通道 |
| 陷入 | Trap | 程序主动触发的一次异常，系统调用靠它进入内核 |
| 全缓冲 | Full Buffering | 攒满缓冲才真正输出；输出到文件时的默认策略 |
| 行缓冲 | Line Buffering | 遇到换行就输出；输出到终端时的默认策略 |

### 321 进程模型与三态

| 术语 | 英文 | 一句话 |
|---|---|---|
| 程序 | Program | 磁盘上的静态文件（代码 + 数据） |
| 进程 | Process | 程序的一次运行：代码 + 资源 + 执行状态的组合 |
| 进程控制块 | Process Control Block | 内核里记录进程信息的结构体，进程的"档案" |
| 虚拟地址空间 | Virtual Address Space | 内核与 MMU 为每进程伪造的"独占整块内存"的假象 |
| 页表 | Page Table | 虚拟地址到物理地址的映射表，每进程一份 |
| 就绪 | Ready | 万事俱备只差 CPU 的状态 |
| 运行 | Running | 正在 CPU 上执行的状态 |
| 阻塞 | Blocked | 等待事件（IO/锁/定时）的状态 |
| 时间片 | Time Slice | 一个进程连续占用 CPU 的最大时长 |

### 322 线程与共享地址空间

| 术语 | 英文 | 一句话 |
|---|---|---|
| 线程 | Thread | 进程内的执行流；同一进程的线程共享地址空间 |
| 线程控制块 | Thread Control Block | 记录单个线程栈指针与寄存器现场的结构 |
| 进程间通信 | IPC | 进程之间交换数据的机制总称：管道/消息队列/共享内存/信号/Socket |
| 管道 | Pipe | 单向字节流通道，常用于父子进程与命令行 `\|` |
| 共享内存 | Shared Memory | 同一块物理页映射到两个地址空间，最快但要自己配锁 |

### 323 竞态与同步原语

| 术语 | 英文 | 一句话 |
|---|---|---|
| 竞态条件 | Race Condition | 多个执行流争同一数据、结果依赖时序的隐患 |
| 临界区 | Critical Section | 访问共享数据、必须互斥执行的那段代码 |
| 原子性 | Atomicity | 一个操作不会被其它执行流从中间插入 |
| 原子操作 | Atomic Operation | 由硬件指令保证不可分割的操作（如 `atomic_fetch_add`） |
| 互斥锁 | Mutex | 保证同一时刻只有一个执行流进临界区，谁锁谁解 |
| 信号量 | Semaphore | 计数型许可，取完即等；允许别的执行流代还 |
| 条件变量 | Condition Variable | 等待某条件成立，必须配锁使用、用 while 重检 |
| 自旋锁 | Spinlock | 拿不到就忙等不睡眠；用于极短临界区与中断上下文 |
| 死锁 | Deadlock | 各方持有对方所需资源、循环等待，永久阻塞 |

### 331 中断异常与上下文切换

| 术语 | 英文 | 一句话 |
|---|---|---|
| 中断 | Interrupt | 外设异步打断 CPU，转向处理函数 |
| 异常 | Exception | 程序自己触发的同步打断（除零、缺页、主动陷入） |
| 中断向量表 | Vector Table | "中断号→处理函数入口"的表，硬件找 ISR 靠它 |
| 中断服务程序 | Interrupt Service Routine | 中断到达后执行的处理函数，讲究快进快出 |
| 上下半部 | Top/Bottom Half | 中断处理的分工：上半部快进快出，重活留给下半部 |
| 前后台系统 | Foreground/Background | 裸机经典结构：大循环后台 + 中断前台 |
| 上下文切换 | Context Switch | 保存当前执行流状态、换另一个上 CPU 的过程 |

### 332 调度策略

| 术语 | 英文 | 一句话 |
|---|---|---|
| 调度器 | Scheduler | 决定"下一个上 CPU 的是谁"的内核模块 |
| 就绪队列 | Ready Queue | 所有就绪任务排的队，调度器从队里挑人 |
| 抢占式调度 | Preemptive Scheduling | 高优先级一就绪立刻打断低优先级 |
| 护航效应 | Convoy Effect | 长任务堵在前面，后面一批短任务一起被拖慢 |
| 老化 | Aging | 等得越久优先级越高，防止低优先级饿死 |
| 优先级反转 | Priority Inversion | 中优先级插队，让高优先级被低优先级间接阻塞 |
| 优先级继承 | Priority Inheritance | 持锁者临时提升到等待者优先级，缓解反转 |

## 缩写速查

| 缩写 | 全称 | 一句话 |
|---|---|---|
| OS | Operating System | 操作系统 |
| PCB | Process Control Block | 进程控制块：内核里的进程档案 |
| TCB | Thread Control Block | 线程控制块：记录线程栈与寄存器现场 |
| ISR | Interrupt Service Routine | 中断服务程序 |
| IPC | Inter-Process Communication | 进程间通信：管道/消息/共享内存等机制总称 |
| RTOS | Real-Time Operating System | 实时操作系统：FreeRTOS/RT-Thread/Zephyr 等 |
| MMU | Memory Management Unit | 内存管理单元：把虚拟地址翻译成物理地址 |
| CFS | Completely Fair Scheduler | Linux 的默认调度器，按虚拟运行时间排序 |
| API | Application Programming Interface | 应用编程接口：程序之间约定的调用面 |

## 易混对

| A vs B | 分界一句话 |
|---|---|
| 程序 vs 进程 | 程序是磁盘上的文件，进程是它的一次运行 |
| 进程 vs 线程 | 进程有独立地址空间，线程共享所属进程的地址空间 |
| 并发 vs 并行 | 并发是"交替上 CPU 看似同时"，并行是"真有多核同时跑" |
| 中断 vs 异常 | 中断是外设异步打断，异常是指令执行中的同步打断 |
| 中断 vs 上下文切换 | 中断可以不换任务就返回；切换只发生在"决定换任务"时 |
| 系统调用 vs 函数调用 | 函数调用留在用户态，系统调用要穿越到内核态 |
| 宏内核 vs 微内核 | 服务都进内核（快但一崩全崩）vs 内核最小化（稳但消息开销） |
| 裸机 vs RTOS | 大循环+中断的前后台 vs 有调度器的多任务 |
| 通用 OS vs RTOS | 吞吐与功能优先 vs 响应时间确定优先 |
| 互斥锁 vs 信号量 | 锁有所有权、谁锁谁解；信号量是计数、别人可代还 |
| 自旋 vs 阻塞 | 自旋烧 CPU 不睡眠（适合极短/中断内），阻塞让出 CPU |
| 抢占 vs 非抢占 | 高优先级能否随时打断低优先级 |
| volatile vs 原子性 | volatile 只保证"每次去内存读"，不保证三步不被插队 |

## 症状反查

| 症状 | 最可能病根 | 去哪册哪节 |
|---|---|---|
| printf 没输出但程序没死 | 输出停在缓冲区没刷新 | 313 §313.5 |
| 两个线程改同一变量结果错乱 | 竞态条件没加互斥 | 323 §323.2 |
| 中断里改的标志主循环看不见 | 缺 volatile，或被优化进寄存器 | 331 §331.3 |
| 程序内存占用只涨不降 | 资源没释放（泄漏思路） | 321 §321.2 +「C 语言」142 |
| 想知道"开机到桌面"之间发生了什么 | 启动链：固件→bootloader→内核→init | 312 §312.2 |
| 嵌入式为什么常不用 Linux | 实时性、资源与启动速度的取舍 | 312 §312.5 |
| 一进中断处理程序就卡死 | ISR 里做了重活/死等 | 331 §331.2 |
| 程序崩了提示非法访问内存 | 用户态踩了受保护地址 | 313 §313.1 |
| 系统"卡一下"又恢复 | 上下文切换或调度延迟 | 331 §331.4 |
| 进程杀不掉、状态是 D | 阻塞在不可中断的内核路径 | 321 §321.2 |
| 高优先级任务莫名超时 | 优先级反转 | 332 §332.3 |
| 低优先级任务永远轮不到 | 无老化，被持续抢占 | 332 §332.1 |
| 加锁后程序变慢很多 | 临界区太大，含 IO | 323 §323.3 |
| 偶发卡死，两个操作同时发生必现 | 死锁 | 323 §323.5 |
