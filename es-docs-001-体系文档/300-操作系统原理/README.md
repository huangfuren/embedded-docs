# 操作系统原理手册

> **一句话**：操作系统 = 硬件与应用之间的总管家——管 CPU 时间、内存、外设与文件；嵌入式无论跑 Linux 还是 RTOS，都是它的形态变体。  
> **读者**：学过 C 与体系结构、想弄清"程序怎么被系统托管"的初学者；要理解 RTOS 与嵌入式 Linux 差异的工程师。  
> **口径**：概念通用为主线，例证 Linux（通用 OS）与 FreeRTOS（RTOS）双线对照；不深入内核源码，版本不绑定。  
> **更新**：2026-11-23  
> **术语表**：单独成册 → [301 术语表](301-术语表.md)。

## 核心概念速览

- **内核**：常驻内存的总管家本体，四条职责都在它身上；应用永远不直接操作硬件（311 §311.2）。
- **进程与线程**：进程是资源容器，线程是执行单位——调度器真正调度的是线程（321 §321.2、322 §322.1）。
- **两态之间只有一扇门**：用户态程序请求内核服务只能走系统调用，代价是换特权级（313 §313.2）。
- **中断是引擎**：硬件不等人，ISR 必须快进快出，重活交给下半部（331 §331.2）。
- **调度没有最优**：时间片、优先级、队列三个旋钮，调哪个都要牺牲别的（332 §332.1）。

## 误解澄清

| # | 误解 | 实际 |
| --- | --- | --- |
| 1 | 操作系统 = 桌面和窗口 | 图形界面只是外壳；内核的调度/内存/文件/驱动才是本体（311 §311.4） |
| 2 | 程序就是进程 | 程序是文件，进程是它的一次运行实例（321 §321.1） |
| 3 | 线程开得越多越快 | 切换有开销，任务多于核数反而互相拖累（321 §321.4） |
| 4 | RTOS 就是精简版 Linux | 单地址空间 + 优先级抢占 vs 完整 OS + 吞吐优先，机制不同（312 §312.5） |
| 5 | 系统调用就是普通函数调用 | 它要换特权级，开销高一个量级（313 §313.3） |
| 6 | 裸机开发不需要懂 OS | 前后台系统就是"没有进程的 OS 思维"（331 §331.5） |
| 7 | 中断处理函数想干啥干啥 | ISR 必须快进快出，重活留给下半部（331 §331.2） |
| 8 | 崩溃都是一样的崩 | 用户态崩溃进程死掉，内核态出错整个系统瘫（313 §313.1） |
| 9 | 加了 volatile 就线程安全了 | 它只保证"每次去内存读"，不保证三步不被插队（331 §331.3） |
| 10 | 优先级设得越高系统越流畅 | 高优先级会饿死低优先级；设错的代价是反转与超时（332 §332.1） |

## 阅读约定

1. **概念通用，例证双线**：机制一律用"Linux（通用 OS）+ FreeRTOS（RTOS）"对照，看清同一原理的两种形态。
2. **不深入源码**：讲机制与数据流，不逐行读内核；版本不绑定，演进敏感处只写模式。
3. **每册结构统一**：导读块 → 目录（★/○ 标记）→ 正文 → 坑表 → 自测 6 题 + 动手任务 2 件 → 下一篇。
4. **跨册引用带册号**：如「计算机体系结构」223 §223.2——所指章节必须真实存在；本板块内节号 = 册号.节序（如 323 §323.1）。
5. **教学节带跟学四件套**：完整示例 → 预期输出（本机实测回填）→ 跟做步骤 → 试一试；本板块实验集中在本机可观察的进程/竞态/缓冲三处，纯原理册（332）只用纸面推演与观察任务，不伪造输出。
