# 153 时间、随机与数学库

> **解决**：三个"随手就能用、但一用就容易错"的标准库——时间的三把尺子精度不同，随机数不设种子就每次一样、设错种子又不可复现，浮点数用 `==` 比较永远失败。这三个坑在日志、定时器、测试与算法题里天天出现。  
> **范围**：`time_t` / `clock_t` / 高精度时钟 · `ctime` 与 `localtime` · `rand`/`srand` 与区间公式 · 模偏置 · `sqrt`/`pow`/`fabs`/`fmod` · 浮点比较与 eps。  
> **口径**：C17；时间数值与 `RAND_MAX` 为本机实录（Windows x64 + GCC 16.2.0），**`rand()` 的具体序列依实现而异，跨平台不保证一致**；`clock()` 的语义分平台：POSIX 量 CPU 时间，Windows（MinGW/UCRT）实测量的是进程启动以来的墙上时间——跨平台别拿它当 CPU 时间，计时要准用 QPC（见 112）。  
> **更新**：2026-11-23  
> **本册导读** ── 必会三点：① `time()` 只到秒、`clock()` 在 Windows 实测是墙上时间（POSIX 才是 CPU 时间）、要毫秒以上用 `clock_gettime`/`timespec_get` ② 随机数必须 `srand` 且**只设一次**，同一份种子给出同一串序列（可复现是用来调试的优点）③ 浮点比较绝不用 `==`，用 `fabs(a-b) < eps`（`0.1+0.2 != 0.3` 实测） ｜ 跟做时长：约 1.5 小时 ｜ 前置：121（类型）、152（格式化输出）。

## 153.1 时间：三把尺子与各自的精度 ★

**定义**：C 标准库给三种"时间"，**精度与含义完全不同**，混用是第一个坑：

| 尺子 | 类型/函数 | 精度 | 量的是什么 | 典型用途 |
|---|---|---|---|---|
| **日历时间** | `time_t` / `time(NULL)` | 秒 | 从 1970-01-01 UTC 起的秒数（Unix 时间戳） | 打日志时间、算日期差 |
| **计时器** | `clock_t` / `clock()` | 毫秒级（本机 `CLOCKS_PER_SEC=1000`） | POSIX 语义=CPU 时间**不含等待**；Windows 实测是墙上时间（含等待） | 粗量代码耗时，跨平台别当 CPU 时间 |
| **高精度挂钟** | `timespec_get` / `clock_gettime` | 纳秒~微秒 | 墙上时间（含等待） | 性能测量、超时控制 |

**完整示例**（[code/153/timedemo.c](../code/153/timedemo.c)）：

```c
#include <stdio.h>
#include <time.h>

int main(void)
{
    time_t now = time(NULL);
    printf("time(NULL) = %lld\n", (long long)now);
    printf("ctime      = %s", ctime(&now));

    struct tm *lt = localtime(&now);
    printf("local      = %04d-%02d-%02d %02d:%02d:%02d\n",
           lt->tm_year + 1900, lt->tm_mon + 1, lt->tm_mday,
           lt->tm_hour, lt->tm_min, lt->tm_sec);

    clock_t c0 = clock();
    volatile double acc = 0;
    for (int i = 0; i < 10000000; i++) acc += i;
    clock_t c1 = clock();
    printf("acc = %.0f\n", (double)acc);
    printf("clock ticks = %ld, CLOCKS_PER_SEC = %ld\n", (long)(c1 - c0), (long)CLOCKS_PER_SEC);
    printf("elapsed = %.3f s\n", (double)(c1 - c0) / CLOCKS_PER_SEC);
    return 0;
}
```

**跟做**：`cd code/153` → `gcc -Wall timedemo.c -o timedemo.exe` → `.\timedemo.exe`。**预期输出（本机实录，时间值随运行时刻变）**：

```text
time(NULL) = 1795414987
ctime      = Mon Nov 23 14:23:07 2026
local      = 2026-11-23 14:23:07
acc = 49999995000000
clock ticks = 26, CLOCKS_PER_SEC = 1000
elapsed = 0.026 s
```

**三处必看的机制**：① **`ctime` 与 `localtime` 返回的都是静态缓冲区**——下一次调用会覆盖它，所以 `char *s1 = ctime(&t1); char *s2 = ctime(&t2);` 之后 `s1` 与 `s2` 指向**同一块内存**（都显示 t2 的时间）。要留住就 `strcpy` 一份（131 §131.4）；② **`clock()` 的单位不是秒**，是 `CLOCKS_PER_SEC` 分之一秒（本机 1000，但**别的平台可能是 1000000**）——所以永远写成 `(c1-c0)/(double)CLOCKS_PER_SEC`，别硬编码 1000；③ **`volatile` 在计时循环里是必要的**：不加的话编译器可能把整个求和循环优化掉，`clock()` 量出 0 秒——这是性能测量最常见的假数据来源。

**时间戳与日期的换算**：`time_t` 是秒数，`struct tm` 是拆好的年月日时分秒，两者用 `localtime`（本地时区）/`gmtime`（UTC）互转。注意 `tm_year` 是**从 1900 起算**、`tm_mon` 是 **0~11**——所以要 `+1900` 与 `+1`（示例里已经写了，这两个偏移是新手的第一道坎）。

**格式化建议**：`strftime(buf, sizeof buf, "%Y-%m-%d %H:%M:%S", lt)` 比手工 `printf` 更省事，也更容易跨平台。

**试一试**：① 在 `printf("acc...")` 之前连调两次 `ctime`（不同时间），观察第一次的结果被覆盖——亲眼看到静态缓冲区；② 把循环上限从 1000 万改成 100 万，重跑看 `clock ticks` 的变化（应该大致按比例缩小）。

## 153.2 随机数：种子、序列与区间公式 ★

**定义**：`rand()` 返回 `[0, RAND_MAX]` 的**伪随机**整数，`srand(seed)` 设定序列起点。**同一份种子给出同一串序列**——这不是缺陷，是特性：调试时要复现，就必须固定种子；要"每次不同"，就用 `time(NULL)` 当种子。

**完整示例**（[code/153/rand_seed.c](../code/153/rand_seed.c)）：

```c
#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    printf("RAND_MAX = %d\n", RAND_MAX);

    srand(42);
    printf("srand(42) -> ");
    for (int i = 0; i < 5; i++) printf("%d ", rand());
    printf("\n");

    srand(42);
    printf("srand(42) again -> ");
    for (int i = 0; i < 5; i++) printf("%d ", rand());
    printf("\n");

    srand(7);
    printf("[1,6] dice x10 -> ");
    for (int i = 0; i < 10; i++) printf("%d ", rand() % 6 + 1);
    printf("\n");
    return 0;
}
```

**跟做**：`gcc -Wall rand_seed.c -o rand_seed.exe` → `.\rand_seed.exe`。**预期输出（本机实录）**：

```text
RAND_MAX = 32767
srand(42) -> 175 400 17869 30056 16083 
srand(42) again -> 175 400 17869 30056 16083 
[1,6] dice x10 -> 2 5 6 3 6 1 3 5 2 5 
```

**三处必看的机制**：① **两次 `srand(42)` 给出完全相同的五个数**——这就是"可复现"的实证，写测试时靠它；② **`RAND_MAX` 只有 32767**（本机实现），意味着 `rand()` 能给的样本非常有限——要更大范围得拼两个 `rand()`；③ **区间公式**：`rand() % (n - m + 1) + m` 把 `[0, RAND_MAX]` 映射到 `[m, n]`（骰子就是 `% 6 + 1`）。

**不调 `srand` 会怎样**：种子默认 0，**每次运行序列完全相同**——调试时是优点（可复现），做游戏或仿真时是硬 bug（每次都一样）。标准做法：程序启动时 `srand((unsigned)time(NULL))` **调一次**。

**模偏置**（进阶坑，值得知道）：`rand() % 6` 在 `RAND_MAX = 32767` 时，32768 不是 6 的倍数（余 2），所以 1、2 两个面出现概率略高。教学场景无所谓；做抽奖、加密**绝对不能用 `rand()`**——那是密码学随机数发生器（`/dev/urandom`、硬件 RNG）的活。

**完整示例**（[code/153/rand_demo.c](../code/153/rand_demo.c)，带种子版）：`srand((unsigned)time(NULL))` 后连打五个 `[22, 94]` 区间的随机数。**本机实录（每次运行都不同，你跑出来的数字必然与这里不一样）**：

```text
num = 79
num = 64
num = 36
num = 61
num = 40
```

**试一试**：① 把 `srand(42)` 改成 `srand(43)`，看五个数全变——种子的一个数字改变整条序列；② 把骰子那行的 `% 6 + 1` 改成 `% 6`，输出变成 0~5——**差一错误的随机版**（`rand() % 6` 的范围是 0~5，不是 1~6）。

## 153.3 数学库：四函数与浮点比较 ★

**定义**：`<math.h>` 里最常用的四个——`sqrt`（开方）、`pow`（幂）、`fabs`（浮点绝对值）、`fmod`（浮点取余）。**注意 `fabs` 而不是 `abs`**：`abs` 是整数版（`<stdlib.h>`），对浮点用会截断成整数。

**完整示例**（[code/153/mathdemo.c](../code/153/mathdemo.c)）：

```c
#include <stdio.h>
#include <math.h>

int main(void)
{
    printf("sqrt(2)      = %.10f\n", sqrt(2.0));
    printf("pow(2, 10)   = %.1f\n", pow(2.0, 10.0));
    printf("fabs(-3.5)   = %.1f\n", fabs(-3.5));
    printf("fmod(7.5, 2) = %.2f\n", fmod(7.5, 2.0));

    double a = 0.1 + 0.2;
    printf("0.1+0.2      = %.17f\n", a);
    printf("0.1+0.2==0.3 ? %d\n", a == 0.3);
    printf("fabs(a-0.3) < 1e-9 ? %d\n", fabs(a - 0.3) < 1e-9);
    return 0;
}
```

**跟做**：`gcc -Wall mathdemo.c -o mathdemo.exe` → `.\mathdemo.exe`。**预期输出（本机实录）**：

```text
sqrt(2)      = 1.4142135624
pow(2, 10)   = 1024.0
fabs(-3.5)   = 3.5
fmod(7.5, 2) = 1.50
0.1+0.2      = 0.30000000000000004
0.1+0.2==0.3 ? 0
fabs(a-0.3) < 1e-9 ? 1
```

**三处必看的机制**：① **`0.1+0.2` 不等于 `0.3`**——二进制浮点无法精确表示 0.1 与 0.2，`%.17f` 直接把误差抖出来（`...00004`），`==` 判出 **0**；② **正确的比较写法是判"足够接近"**：`fabs(a - b) < eps`（本机 eps 取 1e-9 判出 1）——`eps` 取多大取决于业务精度，没有万能值；③ **`fmod(7.5, 2) = 1.5`** 是浮点取余，与整数的 `%`（只能用于整数）不是一回事——`7.5 % 2` 编译不过。

**链接 `-lm` 的事**：Linux 上数学库是独立的（`gcc mathdemo.c -lm`），**Windows 的 MinGW 通常不需要**（本机直接编译通过）。跨平台工程在 Makefile 里统一加 `-lm` 最省事——多写一个参数不会出错。

**常用函数速查**：

| 函数 | 作用 | 坑 |
|---|---|---|
| `sqrt(x)` | 平方根 | `x < 0` 返回 NaN，用前判正负 |
| `pow(x, y)` | x 的 y 次方 | 整数幂用 `x*x` 更快；`pow` 是浮点运算 |
| `fabs(x)` | 浮点绝对值 | 别用 `abs`（那是整数版） |
| `fmod(x, y)` | 浮点取余 | 整数取余用 `%`，两者不能互换 |

**试一试**：① 把 `1e-9` 改成 `1e-20` 再跑最后一行——判出 0（因为误差比 eps 大），体会"eps 不是越小越好"；② 写 `sqrt(-1.0)` 打印结果，看它输出 `nan` 或 `-nan`——浮点的错误不崩溃，只给特殊值（后续判断用 `isnan()`）。

## 153.4 坑表

| # | 现象 | 原因 | 解法 |
|---|---|---|---|
| 1 | 每次运行随机数都一样 | 没调 `srand`（默认种子 0） | 启动时 `srand((unsigned)time(NULL))` 调一次（§153.2） |
| 2 | 序列仍然重复（同一秒内多次启动） | `time(NULL)` 只到秒，同秒内种子相同 | 加进程号/毫秒做混合种子（§153.1） |
| 3 | 循环里每次调 `srand`，随机数不走 | 每轮重设种子 → 序列回到起点 | `srand` 只在启动调一次（§153.2） |
| 4 | `rand() % 6` 得到 0 | 范围是 0~5，不是 1~6 | `rand() % 6 + 1`（§153.2 试一试 ②） |
| 5 | `0.1+0.2 == 0.3` 为假 | 二进制浮点无法精确表示十进制小数 | `fabs(a-b) < eps`（§153.3 实录） |
| 6 | `abs(-3.5)` 得 3 | `abs` 是整数版，浮点被截断 | 用 `fabs`（§153.3） |
| 7 | `7.5 % 2` 编译报错 | `%` 只接受整数 | 用 `fmod(7.5, 2)`（§153.3） |
| 8 | `ctime` 两次调用结果一样 | 返回静态缓冲区，第二次覆盖第一次 | 立即 `strcpy` 存一份（§153.1） |
| 9 | `clock()` 量出 0 秒 | 测量循环被优化掉了 | 累加变量加 `volatile`（§153.1 实录） |
| 10 | Linux 上 `sqrt` 链接失败 | 数学库要单独链接 | 编译命令加 `-lm`（§153.3） |
