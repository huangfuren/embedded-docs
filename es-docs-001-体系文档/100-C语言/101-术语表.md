# 101 术语表

> **这一文档回答**：C 语言词汇的准确定义、两组最容易混用的词的分界、「症状出现时病根在哪」往哪走。  
> **怎么用**：按名字（按册分组）、按缩写（缩写速查）、按易混（易混对）、按症状（症状反查）。  
> **只有一句话**：这里保证「认得出、分得清、找得到」；要落地动作回对应册。

## 按册分组

### 102 C 语言全貌

| 术语 | 英文 | 一句话 |
|---|---|---|
| 编译型语言 | Compiled Language | 先整体翻译成机器码再运行；与解释型逐行执行相对 |
| C 标准 | C Standard | ISO 发布的语言规范；现行主线 C17（C23 已发布，本库仍以 C17 论述） |
| 工具链 | Toolchain | 预处理→编译→汇编→链接一整套程序的总称，核心是 gcc |
| 可执行文件 | Executable | 链接后的最终产物，含机器码与加载信息，操作系统才能运行它 |
| 嵌入式 C | Embedded C | 标准之外面向硬件的扩展约定（寄存器、位操作习惯），语言本体不变 |
| 移植性 | Portability | 换平台重编译即可运行的程度；靠不写平台相关代码换来的 |

### 111 编译四阶段与第一个程序

| 术语 | 英文 | 一句话 |
|---|---|---|
| 预处理器 | Preprocessor | 编译第一阶段：展开 `#include`、替换宏、裁条件编译 |
| 目标文件 | Object File | 汇编产物（.o/.obj）：已翻译的机器码，但地址和库引用还没拼上 |
| 链接器 | Linker | 把目标文件与库拼成可执行文件的最后一环；`undefined reference` 是它的报错 |
| 工具链前缀 | Toolchain Prefix | 交叉编译工具的名字前缀（如 arm-none-eabi-），换前缀即换目标平台 |
| 警告 | Warning | 编译器怀疑有问题但放行；`-Wall` 打开全部常规警告 |
| 构建系统 | Build System | 按规则自动调用工具链的东西；Makefile 是最直接的一种 |
| 交叉编译 | Cross Compilation | 在 A 平台编译出 B 平台的可执行程序 |
| 标识符 | Identifier | 取名符号：字母/数字/下划线，数字不能开头，关键字不可用 |

### 112 调试：从报错到根因

| 术语 | 英文 | 一句话 |
|---|---|---|
| 断点 | Breakpoint | 让程序停在指定源码行的调试手段；`-g` 编译才有行号可停 |
| 栈回溯 | Backtrace | 崩溃时打印调用链（`bt`），从 `#0` 当前帧读到 `#1` 调用者 |
| 优化等级 | Optimization Level | `-O0` 便于调试、`-O2` 便于暴露 UB；两者结果不一致即说明有 UB |
| 金丝雀值 | Canary Value | 在数组两端放哨兵值，越界写会改掉它，用来自查边界 |
| 打点法 | Print Debugging | 在可疑处插入输出验证假设；一次性只验一个假设 |

### 121 变量类型与运算符

| 术语 | 英文 | 一句话 |
|---|---|---|
| 字面量 | Literal | 直接写死在代码里的值：`42`、`0x1F`、`'a'`、`"hi"` |
| 整型提升 | Integer Promotion | 小类型（char/short）参与运算时先升成 int 再算 |
| 运算符优先级 | Operator Precedence | 谁先算谁后算的规则表；拿不准就加括号（`&` 低于 `==`） |
| 占位符 | Placeholder | printf/scanf 的格式说明符，决定按什么类型解释数据 |
| 布尔 | Boolean | 经典 C 无原生类型：0 假、非零真；C99 起有 `_Bool`（121 §121.2），stdbool.h 提供 bool/true/false |
| 补码 | Two's Complement | 机器存储与运算用的编码；负数 = 取反加一，溢出回绕的物理原因 |
| 位运算四模板 | Bit Ops Templates | 置位 `\|=`、清位 `&=~`、翻转 `^=`、测试 `&`——驱动代码的日常 |

### 122 控制流与分支

| 术语 | 英文 | 一句话 |
|---|---|---|
| 短路求值 | Short-circuit Evaluation | `&&`/`\|\|` 左边定生死后右边不再执行（`p && *p` 的安全来源） |
| 穿落 | Fall-through | switch 没有 break 时继续执行下一支；是机制不是错误，漏写才是 |
| 悬空 else | Dangling else | else 绑定**最近**的 if；`-Wdangling-else` 会提醒加括号 |
| 差一错误 | Off-by-one | 循环边界多一少一（`i <= len` vs `i < len`） |
| 值传递 | Pass by Value | C 的函数实参永远是拷贝；想改调用者的变量只能传地址 |

### 123 函数作用域与链接

| 术语 | 英文 | 一句话 |
|---|---|---|
| 原型 | Prototype | 函数先声明后使用的那行签名；没有它新 GCC 直接报错 |
| 栈帧 | Stack Frame | 一次函数调用在栈上占用的那段空间，返回即回收 |
| 作用域 | Scope | 名字有效的代码范围：块级/局部/全局三层，就近原则 |
| 全局静态区 | Static Storage | 全局与 static 成员的家：生命周期最长、有默认零值 |
| 文件私有 | Internal Linkage | static 全局变量/函数只属于本文件，extern 也拿不到 |
| 递归 | Recursion | 函数调用自己；好递归 = 有规律（递进）+ 有出口（回归） |

### 124 预处理与宏

| 术语 | 英文 | 一句话 |
|---|---|---|
| 宏 | Macro | 预处理阶段的文本替换；参数与整体都必须加括号 |
| 条件编译 | Conditional Compilation | 按宏是否定义/取值裁剪代码：`#ifdef` 看定义、`#if` 看值 |
| 头文件守卫 | Include Guard | `#ifndef/#define/#endif` 三件套，防同文件被重复包含 |
| 字符串化 | Stringification | 宏里的 `#` 运算符，把参数变成字符串且不求值 |
| 记号拼接 | Token Pasting | 宏里的 `##` 运算符，把两个记号粘成一个标识符 |

### 131 数组与字符串

| 术语 | 英文 | 一句话 |
|---|---|---|
| 索引 | Index | 元素编号，从 0 开始；最大索引 = 长度 − 1 |
| 哨兵 | Sentinel | `\0` 结束符，标记字符串到哪停；缺它打印会越界读 |
| 遍历 | Traversal | 用循环依次访问容器每个元素的基本功 |
| 字符串字面量 | String Literal | 双引号常量，住只读区（改它是未定义行为，见 133 §133.3） |
| 变长数组 | VLA, Variable Length Array | C99 起：长度运行期才定的栈上数组；声明时不能初始化 |

### 132 结构体、联合与位域

| 术语 | 英文 | 一句话 |
|---|---|---|
| 结构体 | struct | 把多个不同类型成员打包成一个整体 |
| 联合体 | union | 多成员共享同一块内存——同一数据的多种解释 |
| 位域 | Bit Field | 成员按位分配宽度，映射寄存器字段的直译；按底层类型占空间 |
| 枚举 | Enum | 取值有限的类型：枚举项是命名的整数常量，默认从 0 递增 |
| 类型别名 | Type Alias | typedef 给类型改名（如 u8），不造新类型，与原类型等价 |

### 133 指针：地址、步长与解引用

| 术语 | 英文 | 一句话 |
|---|---|---|
| 地址 | Address | 内存中每个字节的编号；取址符 `&` 拿到它 |
| 解引用 | Dereference | 按指针里存的地址去访问那格内存：`*p` |
| 步长 | Stride | 指针 +1 实走的字节数 = 指向类型的宽度（`int*` 走 4、`char*` 走 1） |
| 野指针 | Wild Pointer | 没初始化或指向已失效内存的指针；内容随机，最危险 |
| 空指针 | Null Pointer | 明确指向"什么都不指向"的指针（NULL）；解引用必崩但崩得可预期 |
| 悬空指针 | Dangling Pointer | 指向已释放/已失效内存的指针；free 后置 NULL 防它 |

### 141 内存四区与对象生命周期

| 术语 | 英文 | 一句话 |
|---|---|---|
| 内存布局 | Memory Layout | 进程内存的分区：代码段/数据段/栈/堆 |
| 存储期 | Storage Duration | 变量的生命长度：静态/自动/分配三种（四区各对应一种） |
| 内存泄漏 | Memory Leak | malloc 了没 free，内存越用越少 |
| 段错误 | Segmentation Fault | 访问了没权限的内存地址，操作系统强制终止进程（退出码 139） |
| 缓冲区溢出 | Buffer Overflow | 写数据超出数组边界，踩到相邻内存——安全漏洞的头号来源 |

### 142 指针进阶与动态内存

| 术语 | 英文 | 一句话 |
|---|---|---|
| 函数指针 | Function Pointer | 存函数入口地址的指针：`返回值 (*名)(形参)` |
| 回调 | Callback | 函数作参数传给别人，对方在合适时机"回头调用"它 |
| 动态内存 | Dynamic Memory | malloc/calloc/realloc/free 管的堆空间，手动释放 |
| 指针数组 | Array of Pointers | `int *a[n]`：装 n 个指针的数组 |
| 数组指针 | Pointer to Array | `int (*p)[n]`：指向"整个数组"的指针，+1 跨 n 个元素 |

### 143 对齐、字节序与内存布局

| 术语 | 英文 | 一句话 |
|---|---|---|
| 内存对齐 | Memory Alignment | 成员落在自身宽度的整数倍地址上，代价是 padding |
| 填充 | Padding | 对齐留下的空隙字节；重排成员可从 12 缩到 8 |
| 偏移量 | Offset | offsetof 给出的"成员距结构体起点的字节数"，对齐规则观察窗 |
| 打包 | Packing | `#pragma pack(n)` 压掉 padding；报文与寄存器块才用，内部结构别用 |
| 字节序 | Endianness | 多字节数据在内存中的字节顺序；低字节在低地址叫小端 |
| 小端与大端 | Little / Big Endian | x86/ARM 默认小端；网络序是大端，故有 htonl/ntohl 一族 |

### 151 文件IO与缓冲

| 术语 | 英文 | 一句话 |
|---|---|---|
| 流 | Stream | 数据进出程序的通道；方向以程序自己为参照物 |
| 缓冲区 | Buffer | 数据的中转站；输入残留 `\n` 与忘 fclose 丢数据都是它 |
| EOF | End Of File | 文件结束标志（-1）；fgetc 读完返回它，要用 int 接 |
| 文件模式 | Open Mode | fopen 的 "r"/"w"/"a"：读、覆盖写、追加写；b 后缀走二进制 |
| FILE | File Stream Type | 流对象的类型；fopen 返回它，NULL 表示打开失败 |
| 标准错误 | stderr | 错误信息专用输出流；默认不被 `>` 重定向捕获 |

### 152 命令行参数与字符串格式化

| 术语 | 英文 | 一句话 |
|---|---|---|
| 命令行参数 | Command-line Argument | main 的 argc/argv 收的参数；argv[0] 是程序自身路径 |
| 字符串格式化 | String Formatting | sprintf/sscanf 在字符串与数据之间按占位符互转 |
| 变参函数 | Variadic Function | `...` 声明的"参数个数不定"函数；printf 家族的底座 |

### 153 时间、随机与数学库

| 术语 | 英文 | 一句话 |
|---|---|---|
| 时间戳 | Unix Timestamp | 从 1970-01-01 UTC 起的秒数；`time(NULL)` 取 |
| CPU 时间 | CPU Time | POSIX 语义=进程占用 CPU 时长**不含等待**；Windows 的 clock() 实测是墙上时间（153），单位是 CLOCKS_PER_SEC |
| 伪随机数 | Pseudo-random Number | rand() 的序列由种子唯一决定，可复现；不是真随机 |
| 种子 | Seed | `srand(seed)` 设的序列起点；同种子同序列，启动时只设一次 |
| 模偏置 | Modulo Bias | `rand() % n` 在 RAND_MAX+1 不是 n 倍数时分布略不均 |
| 浮点容差 | Epsilon | 浮点比较用 `fabs(a-b) < eps`，绝不用 `==` |
| NaN | Not a Number | 无效浮点运算（如 `sqrt(-1)`）的结果；用 `isnan()` 判断 |

### 161 复杂度：时间与空间

| 术语 | 英文 | 一句话 |
|---|---|---|
| 时间复杂度 | Time Complexity | 基本操作次数随规模 n 的渐进增长 |
| 大 O 表示法 | Big O Notation | 只留最高次项的渐进记法：3n+3→O(n)、n²+n→O(n²) |
| 对数阶 | Logarithmic | 每次排除一半的算法（二分查找）；log₂1000≈10 |
| 空间复杂度 | Space Complexity | 算法额外开的格子数；递归深度计入栈空间 |
| 增长阶梯 | Growth Ladder | O(1)<O(log n)<O(√n)<O(n)<O(n log n)<O(n²)<O(n³) |

### 162 动态数组与链表

| 术语 | 英文 | 一句话 |
|---|---|---|
| 动态数组 | Dynamic Array | malloc+realloc 的可增长数组：data/length/capacity 三件套 |
| 容量 | Capacity | 分到的总格子数；length==capacity 时扩容 |
| 扩容 | Resize | realloc 换更大内存块（倍增 ×2 策略），旧内容原样复制 |
| 节点 | Node | 链表的基本单元：数据域 + 指针域 |
| 指针域 | Next Pointer | 节点里存"下一个节点地址"的成员 |
| 头插法 | Head Insertion | 新节点接在 header 前：两次赋值，不搬已有节点 |

### 163 栈与队列

| 术语 | 英文 | 一句话 |
|---|---|---|
| 栈 | Stack | 只在栈顶一端进出的线性结构；后进先出 LIFO |
| 栈顶 | Top | 唯一允许 push/pop 的一端（实现上 = data[length-1]） |
| 压栈与弹栈 | Push / Pop | 入栈与出栈；空栈 pop 返回 false 不崩 |
| 队列 | Queue | 队尾进、队首出的线性结构；先进先出 FIFO |
| 队首与队尾 | Front / Rear | 允许删除的一端 / 允许插入的一端 |
| 假溢出 | False Overflow | front 后移后前段格子废了；取模绕回（循环队列）治好 |

### 164 查找与排序

| 术语 | 英文 | 一句话 |
|---|---|---|
| 顺序查找 | Linear Search | 从头逐个比，O(n)，无前提 |
| 二分查找 | Binary Search | 有序前提下每次排除一半，O(log n)；返回 -1 表示没找到 |
| 冒泡排序 | Bubble Sort | 相邻比较大数右沉；O(n²) 教学标本 |
| 快速排序 | Quick Sort | 基准分区+递归两半；平均 O(n log n) |
| 基准 | Pivot | 分区的参照元素；归位后左边都 ≤ 它、右边都 ≥ 它 |

### 165 散列与树

| 术语 | 英文 | 一句话 |
|---|---|---|
| 哈希表 | Hash Table | 数组+链表（+红黑树）组合：哈希函数决定元素住哪个桶 |
| 哈希函数 | Hash Function | 把键映射成桶下标的逻辑；由程序员决定 |
| 冲突与挂链 | Collision / Chaining | 两键同桶：桶内链表把冲突元素串起来 |
| 红黑树 | Red-Black Tree | 自平衡二叉查找树；五性质保证查找稳定 O(log n) |
| 二叉查找树 | BST | 左小右大的二叉树；顺序插入会退化成链表 |
| 选型 | Selection | 把高频操作分配给对它便宜的结构（162~165 合看） |

## 易混对

| A vs B | 分界一句话 |
|---|---|
| 声明 vs 定义 | 声明说"有这么个东西"（可多次），定义说"它在这"（只能一次） |
| 编译 vs 链接 | 编译管单个文件内部对不对，链接管多个文件之间接得上吗 |
| 栈 vs 堆 | 栈自动回收、快、小；堆手动 malloc/free、慢、大、会泄漏 |
| 数组名 vs 指针 | 数组名多数场合退化成首元素地址，但 sizeof 和 & 上暴露真身 |
| `'a'` vs `"a"` | 单引号是一个字符（int），双引号是带 `\0` 的字符数组 |
| `NULL` vs `'\0'` | NULL 是空指针（地址 0），`'\0'` 是字符串结尾的数值 0 字符 |
| `=` vs `==` | `=` 赋值，`==` 判断相等；写在 if 里是高频事故 |
| 形参 vs 实参 | 形参是函数签名的占坑名字，实参是调用时塞进去的值 |
| 头文件 vs 源文件 | .h 放声明（给别人看），.c 放实现（给自己跑） |
| 野指针 vs 空指针 | 野指针指向随机处（不可预期），空指针明确指向无效处（可预期崩溃） |
| 常量指针 vs 指针常量 | `const int *p` 锁值（不能通过 p 改数据），`int *const p` 锁指向 |
| 指针数组 vs 数组指针 | `int *a[n]` 是装指针的数组；`int (*p)[n]` 是指向整个数组的指针 |
| sizeof vs strlen | sizeof 数含 `\0` 的总格子（编译期），strlen 数有效字符（运行期） |
| malloc vs calloc | malloc 开辟后是垃圾值；calloc 清零；realloc 保旧内容扩容 |
| `abs` vs `fabs` | abs 是整数绝对值（截断小数），fabs 才是浮点绝对值 |
| `time` vs `clock` | time 是日历秒（含等待）；clock 在 POSIX 是 CPU 时间（不含等待），Windows 实测为墙上时间（153） |
| `rand` vs `srand` | rand 取下一个数，srand 设序列起点；srand 只在启动调一次 |
| 自然对齐 vs `pack(1)` | 前者按成员宽度对齐（快、占空间），后者紧贴（省空间、可能变慢） |
| 小端 vs 大端 | 低字节在低地址 vs 高字节在低地址；网络序用大端 |
| 宏 vs 函数 | 宏是文本替换（无类型检查、参数带副作用会翻倍），函数有调用与类型检查 |
