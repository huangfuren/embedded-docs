# C 语言手册

> **一句话**：C 是嵌入式的母语——直接操作内存、贴着硬件跑；本板块二十册从"跑起第一个程序"一路立到"数据结构与算法"，是全库的语言地基。  
> **读者**：零基础或语法残缺的嵌入式初学者；从运维/软件方向转行、想补"软硬结合"地基的工程师。  
> **口径**：C17 主线（C11/C23 差异注记），演示用 GCC 16.2.0（Windows 用 w64devkit，Linux/macOS 自带），编辑器 VS Code，不绑定 IDE。  
> **更新**：2026-11-23  
> **术语表**：单独成册 → [101 术语表](101-术语表.md)。

## 核心概念速览

- **类型 = 宽度 + 解释**：同一串二进制按 int 和按 char 读，结果完全不同；溢出是回绕不是报错（121）。
- **实参永远是拷贝**：想改调用者的变量，唯一的办法是把地址交出去（122 / 133）。
- **指针的步长由指向的类型决定**：`int*` +1 走 4 字节，`char*` +1 走 1 字节；但指针自己的宽度恒为平台字长（133）。
- **四区里只有堆要你操心**：代码段与数据段随程序生死，栈自动回收，malloc 来的必须 free（141 / 142）。
- **越界的危险在于不崩**：C 不做边界检查，静默改坏相邻数据比崩溃更难查（141 / 112）。
- **对齐与字节序是跨平台的共同坑**：结构体大小随编译器变、多字节数据随机器变反，报文一律逐字节解析（143）。

## 误解澄清

| # | 误解 | 实际 |
|---|---|---|
| 1 | 开了 `-Wall` 没警告就是没问题 | 未初始化检查的覆盖随优化等级与形态变化，`-O0` 常漏报（112；GCC 16 对部分形态 `-O0` 也会报——131/123/142 实录） |
| 2 | `long` 一定是 8 字节 | Windows 是 4 字节（LLP64）；嵌入式用 `int32_t` 钉死宽度（121） |
| 3 | 溢出会报错 | 有符号溢出是未定义行为，`-O0` 下静默回绕成负数（121） |
| 4 | `char` 就是字符 | `char` 是 1 字节整数；"字符"只是它的一种解释（121 / 131） |
| 5 | 数组有长度属性 | C 数组没有 `length`，长度靠 `sizeof` 现算且只在定义处有效（131） |
| 6 | 字符串是独立类型 | 它就是末尾带 `\0` 的 char 数组，没有 `\0` 就一路读过界（131） |
| 7 | 越界会崩 | 多数越界不报错，只是静默改坏相邻数据（141） |
| 8 | 指针 `+1` 就是加一个字节 | 走的是"一个元素"，由指向类型决定步长（133） |
| 9 | `free` 之后内存就没了 | 内存被收回备用，你的指针还指着它——悬空指针（141 / 142） |
| 10 | 结构体大小 = 成员之和 | 对齐 padding 会让它变大，重排成员能白省（132 / 143） |
| 11 | 浮点可以用 `==` 比较 | `0.1+0.2 != 0.3`；一律 `fabs(a-b) < eps`（153） |
| 12 | 宏就是"更快的函数" | 宏是文本替换：无类型检查，参数带副作用会执行两次（124） |

## 阅读约定

1. **每册结构统一**：导读块（必会三点 ｜ 跟做时长 ｜ 前置）→ 目录 → 正文 → 坑表 → 自测 6 题 + 动手任务。
2. **教学节带跟学四件套**：完整示例 → 预期输出（本机实测回填）→ 跟做步骤 → 试一试；"能看懂"不算完成，"能跟着做"才算。
3. **打印的输出都是真跑出来的**：每册"预期输出"都是本机 GCC 16.2.0 实测，不是编出来好看的；数字对不上就是自己抄错了。地址类数值每次运行都会变，看**差值**不看绝对值。
4. **跨册引用带册号**：如「133 §133.2」——所指章节必须真实存在。
5. **重点标记**：节标题带 ★（必会）/ ○（拓展），必会节点 3~5 个（目录表与标题各标一次）；时间紧只啃 ★。
6. **危险用法标注** ⚠️：会崩溃、会越界、会写只读区的示例一律先标后果再给代码。
